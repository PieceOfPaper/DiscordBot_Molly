# 마물 퇴치 증표 기획서

> 문서 상태: 구현 전 기획 확정안  
> 최종 갱신: 2026-09-28  
> 관련 문서: [출석 기획서](../attendance/README.md), [배틀 예측 기획서](../battle/prediction.md)

## 1. 개요

`마물 퇴치 증표`는 몰리의 출석과 배틀 예측을 연결하는 서버별 놀이 재화다. 마비노기 모바일에서 익숙한 명칭을 빌려오지만 실제 게임 재화와는 연동되지 않는다.

초기 버전에서는 출석으로만 획득하고 배틀 승부 예측에만 사용한다. 별도의 레벨·장비·상점·성장 경쟁은 만들지 않는다.

### 핵심 한 줄

> 하루 한 번 가볍게 받고, 같은 Discord 서버의 배틀을 함께 구경하며 사용하는 몰리 전용 놀이 재화.

## 2. 명칭과 표시 규칙

- 공식 명칭: `마물 퇴치 증표`
- 사용자 사이의 줄임말: `증표`
- 내부 식별자 예시: `molly_token`
- 몰리가 설명·안내·오류 메시지에서 재화 이름을 말할 때는 항상 `마물 퇴치 증표`라고 표기하고, 클래스 이름처럼 **이름 바로 앞에 증표 이모지를 고정으로 붙인다**.
- 재화 이름을 생략하고 수량만 표시하는 UI에는 **몰리봇 전용 증표 이모지**를 수량 바로 앞에 붙인다.
- 이모지와 이름·숫자 사이에는 공백을 넣지 않는다.
- Discord는 임베드 제목·필드 이름·꼬리말과 슬래시 명령 설명에서 서버 이모지를 그리지 않는다. 이런 곳에는 증표 이름을 쓰지 않고 본문으로 옮긴다(슬래시 명령 설명은 예외적으로 이름만 쓴다).

표시 예시:

| 상황 | 표기 |
| --- | --- |
| 공식 안내 | `(증표 이모지)마물 퇴치 증표 10개를 받았습니다.` |
| 버튼·배율표·간단 잔액처럼 이름을 생략하는 곳 | `(증표 이모지)10개` |
| Discord 실제 출력 예시 | `<:molly_token:EMOJI_ID>10개` |

이모지 이름은 `molly_token`이다. 그림은 `assets/currency_emojis/molly_token.png`에 두면 봇이 시작할 때 봇 전용 이모지(Application Emoji)로 등록한다(`Currency/MollyToken.cs`). 등록 전이거나 등록에 실패하면 이모지 없이 `마물 퇴치 증표 10개`로 표기하여 의미가 사라지지 않게 한다. 코드에서는 이름 `MollyToken.Label`, 문장용 `MollyToken.Named(n)`, 이름 생략용 `MollyToken.Amount(n)`을 쓰고, 도움말처럼 미리 써둔 안내문은 `MollyToken.Decorate`로 이모지를 붙인다.

## 3. 소유 범위

- 보유량은 Discord 서버별로 분리한다.
- 계정 키는 `(guild_id, user_id)`다.
- 다른 서버의 잔액을 합산하거나 이전할 수 없다.
- 사용자 간 직접 송금은 제공하지 않는다.
- DM에서는 조회·획득·사용할 수 없다.
- 서버를 나갔다가 돌아오더라도 같은 Discord 사용자 ID라면 기존 잔액을 유지한다.

## 4. 획득과 사용

### 4.1 초기 획득처

- 출석부의 `출석` 버튼을 눌러 하루 한 번 획득한다.
- 지급량은 Google Sheets의 `증표규칙` 시트에서 관리한다.
- 연속 출석, 개근, 추가 과제 보상은 초기 범위에 포함하지 않는다.

### 4.2 초기 사용처

- 해당 서버에서 진행되는 배틀 승부 예측에 건다.
- 예측은 참가자의 재화를 한쪽으로 새로 발행하는 기능이 아니라 결과에 따라 참가자 사이에 재분배하는 기능이다.
- 배틀 결과가 무효이거나 정산할 수 없으면 전액 환불한다.

### 4.3 향후 확장 원칙

새 획득처나 사용처는 추가할 수 있지만 다음 조건을 만족해야 한다.

- 매일 여러 과제를 강요하는 숙제 구조가 아닐 것
- 먼저 시작한 사람에게 영구적인 전투 우위를 주지 않을 것
- 몰리의 짧고 가벼운 놀이를 직접 돕는 용도일 것
- 재화가 없다는 이유로 기존 핵심 기능을 이용하지 못하게 하지 않을 것

## 5. 데이터 설계

### 5.1 계정

`currency_accounts`

| 필드 | 의미 |
| --- | --- |
| `guild_id` | Discord 서버 ID |
| `user_id` | Discord 사용자 ID |
| `balance` | 현재 보유량 |
| `created_at` | 최초 생성 시각 |
| `updated_at` | 마지막 변경 시각 |

`(guild_id, user_id)`를 유일 키로 사용한다. 잔액은 음수가 될 수 없다.

### 5.2 거래 원장

`currency_transactions`

| 필드 | 의미 |
| --- | --- |
| `transaction_id` | 거래 ID |
| `guild_id` | Discord 서버 ID |
| `user_id` | Discord 사용자 ID |
| `amount` | 증감량. 지급은 양수, 차감은 음수 |
| `balance_after` | 거래 후 잔액 |
| `reason_type` | 변경 사유 |
| `reference_id` | 출석·예측 등 원인 데이터의 ID |
| `created_at` | 처리 시각 |

초기 `reason_type`:

- `attendance_reward`
- `prediction_bet`
- `prediction_payout`
- `prediction_refund`

운영자 조정(`admin_adjustment`)은 초기 범위에서 제외했다. 증표 사용처가 늘어 필요해지면 사유와 명령을 함께 추가한다.

잔액 변경과 원장 기록은 하나의 DB 트랜잭션으로 처리한다. `(guild_id, user_id, reason_type, reference_id)`를 유일 키로 두어 같은 보상이 재시도되어도 중복 지급되지 않게 한다.

구현은 `Currency/MollyTokenStore.cs`다. 출석·예측처럼 자기 기록과 증표 변경을 함께 묶어야 하는 기능은 같은 DB(`molly.sqlite`)의 연결·트랜잭션으로 정적 `MollyTokenStore.ApplyAsync(connection, transaction, ...)`를 호출하고 커밋·롤백을 직접 한다. 여러 사람의 정산·환불은 `ApplyAllAsync`로 한 트랜잭션에 처리한다.

## 6. Google Sheets 규칙

수치는 `증표규칙` 시트(gid `1750775172`, 설정 `GoogleSheets:TokenRuleSheetId`)에서 관리한다. 코드에는 서비스가 시작될 수 있는 안전한 기본값만 둔다.

시트에는 구조(헤더)만 먼저 만들었다. 각 규칙 행은 증표를 쓰는 기능(출석·예측 등)을 구현할 때 그 기능이 필요한 ID로 추가하고, 코드에서는 `Program.instance.TokenRules`의 `Current.GetInteger(ID, 기본값)`처럼 자기 ID와 코드 기본값을 함께 넘겨 읽는다. 행이 없거나 `활성화`가 FALSE이거나 자료형이 다르면 기본값을 쓴다. 사용 직전에 `EnsureFreshAsync`로 갱신한다.

권장 필드:

| 필드 | 의미 |
| --- | --- |
| `ID` | 코드에서 참조하는 고정 키 |
| `활성화` | 규칙 사용 여부 |
| `값` | 실제 값 |
| `자료형` | `정수`·`실수`·`문자열`·`정수목록`(`\|`로 구분, 예: `10\|50\|100`) |
| `최소값` | 허용 최소값 |
| `최대값` | 허용 최대값 |
| `단위` | 개·시간·비율 등 |
| `설명` | 운영자용 설명 |
| `비고` | 추가 메모 |

ID는 영어 소문자로 시작하고 영어 소문자·숫자·밑줄만 쓴다. `활성화`는 TRUE/FALSE다. 최소값·최대값은 숫자 규칙에만 쓰고 비워두면 제한이 없으며, `정수목록`은 각 원소에 적용한다. 비활성화 행도 형식을 검사한다. `값` 열에 숫자와 문자열이 섞이므로 gviz가 아닌 export CSV로 읽는다.

초기 규칙 후보는 출석 지급량, 예측 최소 금액, 베팅 단위, 빠른 선택 금액, 최대 베팅 비율·수량이다. 구체적인 수치는 구현 직전에 확정한다.

시트 로딩에 실패하거나 값이 유효하지 않으면 마지막 정상 스냅샷을 유지한다. 정상 스냅샷이 한 번도 없다면 코드의 안전한 기본값을 사용하고 오류를 기록한다.

## 7. 운영·안전 원칙

- 모든 지급·차감·환불은 원장으로 추적할 수 있어야 한다.
- 잔액 확인과 차감은 같은 트랜잭션에서 처리하여 중복 클릭이나 동시 요청으로 초과 사용되지 않게 한다.
- 봇 재시작 후에도 잔액과 미정산 내역을 복구할 수 있어야 한다.
- 운영자 조정은 사유를 남기고 일반 지급과 구분한다.
- 실제 마비노기 모바일 재화로 오해하지 않도록 최초 안내와 도움말에 `몰리 전용 놀이 재화`임을 명시한다.

## 8. 초기 범위에서 제외할 것

- 실제 게임 재화와의 교환 또는 연동
- 사용자 간 송금
- 서버 간 잔액 이전
- 증표 상점
- 별도 레벨·장비·강화
- 연속 출석·개근 보너스
- 현금 또는 유료 재화와의 교환
- 보유량 랭킹

## 9. 구현 전 확인 사항

- 몰리봇 전용 증표 이모지: `assets/currency_emojis/molly_token.png`(128×128), 이름 `molly_token`으로 확정.
- 출석 지급량과 배틀 베팅 관련 수치: 각 기능을 구현할 때 `증표규칙` 시트에 추가한다.
- 잔액 조회: `/가방`으로 확정. 이 서버의 보유량을 본인에게만 보여준다. 나중에 보관할 것이 생기면 같은 명령에 줄을 더한다.
- 운영자 조정: 초기 버전에서 제외.

## 10. 완료 조건

- 서버별 잔액이 완전히 분리된다.
- 출석 보상과 예측 정산이 중복 처리되지 않는다.
- 모든 잔액 변경을 원장에서 확인할 수 있다.
- 이름 없는 수량 표기가 `(증표 이모지)10개` 형식을 지킨다.
- 몰리의 문장에서는 `마물 퇴치 증표`라는 풀네임을 사용한다.
- 오류·취소·재시작 상황에서 증표가 유실되거나 복제되지 않는다.
