# 개발 리뷰 전달 규칙

이 디렉터리는 GPT가 저장소와 Google Sheets 데이터를 검토한 결과를 Codex 또는 Claude Code에 전달하기 위한 공간이다.

리뷰는 확정 기획서가 아니다. 사용자의 판단 없이 리뷰 내용만 보고 코드를 자동으로 수정하지 않는다.

## 디렉터리

- `pending/`: 아직 구현 여부가 결정되지 않았거나 구현 중인 리뷰
- `completed/`: 구현과 검증이 끝난 리뷰

## 상태

| 상태 | 의미 |
| --- | --- |
| `검토안` | GPT가 제안한 단계. 구현하지 않는다. |
| `승인` | 사용자가 반영을 명시적으로 요청한 상태 |
| `반영 중` | Codex 또는 Claude Code가 작업 중인 상태 |
| `완료` | 구현과 검증이 끝난 상태 |
| `보류` | 현재는 반영하지 않는 상태 |

사용자가 현재 요청에서 “검토 내용을 반영해줘”, “필수 수정만 적용해줘”처럼 구현 범위를 명시하면 해당 범위에 대한 승인으로 본다. 표현이 모호하거나 항목별 선택이 필요하면 구현 전에 질문한다.

## 리뷰 문서 필수 항목

- 상태
- 작성일
- 검토한 저장소 커밋
- 시트 검토 시각 또는 기준
- 검토 대상
- 결론
- 잘된 점
- 필수 수정 제안
- 선택 개선 제안
- 유지할 부분
- 완료 조건
- 구현 기록

## 작업 흐름

1. GPT가 현재 저장소와 최신 시트를 확인한다.
2. `pending/`에 `검토안` 문서를 작성한다.
3. 사용자가 검토 내용을 판단하고 반영 범위를 정한다.
4. Codex 또는 Claude Code가 승인된 범위만 구현한다.
5. 코드, 시트, 기획서 사이에 충돌이 있으면 임의로 결정하지 않고 사용자에게 알린다.
6. 구현 후 변경 파일과 시트, 실행한 검증, 미반영 항목을 `구현 기록`에 남긴다.
7. 모든 승인 항목이 끝나면 상태를 `완료`로 바꾸고 문서를 `completed/`로 이동한다.

## 주의사항

- 리뷰의 기준 커밋보다 구현이 크게 바뀌었다면 최신 상태를 다시 검토한다.
- 시트는 Git 커밋에 고정되지 않으므로 구현 직전에 최신 값을 다시 읽는다.
- `검토안`과 `보류` 항목은 다른 작업에 끼워 넣지 않는다.
- 리뷰 반영으로 확정된 설계가 달라지면 관련 기획서도 함께 갱신한다.
- 문서만 수정한 커밋은 `.github/workflows/ci.yml`의 경로 제외 설정에 따라 배포하지 않는다.
