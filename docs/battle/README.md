# 몰리 놀이터: 배틀 기획서

> 문서 상태: 초안  
> 최종 갱신: 2026-09-18  
> 장르: Discord 기반 텍스트 오토배틀러 / 채팅형 전투 시뮬레이터

## 1. 개요

몰리 놀이터의 배틀은 Discord 사용자가 자신의 마비노기 모바일 캐릭터를 등록하고, 다른 사용자의 캐릭터에게 도전하여 자동으로 전투하는 텍스트 기반 게임이다.

전투 중에는 플레이어가 매 턴 명령을 입력하지 않는다. 몰리가 두 캐릭터의 클래스, 능력치, 스킬을 바탕으로 행동을 결정하고 전투 상황을 텍스트로 중계한다. 참가자는 짧은 전투 로그를 감상하고 결과를 확인한다.

```text
종잇장이 핏피에게 일반 공격!
치명타! 456의 피해를 입혔습니다!
핏피는 아직 끄떡없습니다!
```

### 1.1 핵심 한 줄

> 마비노기 모바일의 실제 캐릭터 정보와 클래스 스킬을 이용해 몰리가 진행하는 Discord용 텍스트 자동전투 게임.

### 1.2 용어

| 용어 | 의미 |
| --- | --- |
| 캐릭터 | Discord 사용자가 등록한 마비노기 모바일 캐릭터 |
| 도전자 | `/배틀` 명령을 실행한 사용자 |
| 상대 | 배틀 대상으로 지정된 Discord 사용자 |
| 놀이터 | 전투 로그가 출력되는 별도 공간. 정확한 구현 방식은 미정 |
| 전투 스냅샷 | 전투 시작 시 고정한 캐릭터 클래스와 능력치 |
| 전투 이벤트 | 공격, 피해, 치명타, 회복, 상태 이상 등 전투 중 발생한 사건 |

## 2. 기획 목표

- 기존 랭킹 조회 기능을 놀이 콘텐츠로 확장한다.
- 실제 캐릭터의 클래스와 능력치를 전투에 반영한다.
- Google Sheets에서 관리하는 클래스·스킬 데이터를 활용한다.
- 플레이어의 지속적인 조작 없이도 짧고 재미있는 전투를 제공한다.
- 일반 채팅을 방해하지 않는 독립적인 전투 공간을 사용한다.
- 전투 결과가 능력치만으로 완전히 고정되지 않도록 클래스와 스킬, 적절한 무작위성을 반영한다.
- 이후 전적, 토너먼트, 관전자 기능 등으로 확장할 수 있는 구조를 만든다.

## 3. 초기 범위에서 제외할 것

다음 기능은 초기 버전에 포함하지 않는다.

- 전투 중 플레이어의 실시간 스킬 선택
- 관전자의 전투 개입
- 장비 등록 및 장비 강화
- 별도의 캐릭터 레벨업과 성장 재화
- 포인트 상점과 유료성 재화
- 시즌 보상
- 토너먼트
- AI를 이용한 실시간 전투 문장 생성
- 생활력과 매력의 복잡한 전투 시스템

## 4. 사용자 흐름

### 4.1 캐릭터 등록

예상 명령 형식:

```text
/캐릭터등록 서버:칼릭스 캐릭터이름:종잇장
```

진행 과정:

1. 사용자가 서버와 캐릭터 이름을 입력한다.
2. 몰리가 마비노기 모바일 랭킹에서 캐릭터를 검색한다.
3. 검색 결과가 없거나 여러 결과를 구분할 수 없으면 등록하지 않는다.
4. 검색 결과를 사용자에게 보여주고 등록 여부를 확인한다.
5. 확인하면 Discord 사용자와 캐릭터를 연결하여 DB에 저장한다.
6. 기존에 등록한 캐릭터가 있다면 변경 여부를 확인한다.

등록 시 확보할 후보 데이터:

- Discord 사용자 ID
- Discord 서버 ID
- 마비노기 모바일 서버
- 캐릭터 이름
- 현재 클래스
- 전투력
- 생활력
- 매력
- 각 랭킹 및 순위
- 마지막 조회 시각

### 4.2 캐릭터 조회 및 갱신

필요할 가능성이 높은 보조 명령:

```text
/내캐릭터
/캐릭터갱신
/캐릭터변경
/캐릭터해제
```

랭킹 데이터를 매 배틀마다 새로 수집하면 전투 시작이 느려지고 외부 사이트 장애의 영향을 받는다. 따라서 DB에 마지막 정상 데이터를 저장하고 일정 시간마다 갱신하거나 사용자가 직접 갱신하는 방식을 고려한다.

### 4.3 배틀 신청

예상 명령 형식:

```text
/배틀 상대:@핏피
```

기본 흐름:

1. 도전자와 상대가 모두 캐릭터를 등록했는지 확인한다.
2. 상대방에게 수락·거절 버튼이 포함된 도전 메시지를 보낸다.
3. 제한 시간 안에 수락하면 놀이터를 생성한다.
4. 두 캐릭터의 전투 시작 시점 능력치를 스냅샷으로 저장한다.
5. 몰리가 자동전투를 진행한다.
6. 전투 결과와 주요 이벤트를 저장한다.
7. 결과 요약을 출력한다.
8. 놀이터는 일정 시간이 지나면 닫거나 보관한다.

예외 처리 후보:

- 자기 자신에게 도전
- 등록하지 않은 사용자에게 도전
- 상대방이 거절하거나 응답하지 않음
- 이미 다른 배틀에 참여 중
- 외부 랭킹 조회 실패
- 클래스 또는 스킬 데이터가 없음
- 배틀 도중 봇 재시작

## 5. 전투 공간

전투는 일반 채팅에 영향을 주지 않는 별도 공간에서 진행한다.

구현 후보:

| 방식 | 장점 | 단점 |
| --- | --- | --- |
| 배틀마다 스레드 생성 | 기존 채널과 분리되고 전투별 기록이 명확함 | 스레드가 많이 누적될 수 있음 |
| 고정 놀이터 채널 사용 | 구조가 단순하고 관리가 쉬움 | 여러 배틀이 동시에 진행되면 로그가 섞임 |
| 임시 채널 생성 | 완전한 분리 가능 | 권한과 채널 생성·삭제 관리가 복잡함 |
| 하나의 메시지를 계속 수정 | 채널 도배가 적음 | 전투가 진행되는 느낌이 약하고 과거 로그를 보기 어려움 |

현재 권장 후보는 **배틀마다 스레드를 생성하고, 종료 후 잠그거나 자동 보관하는 방식**이다.

## 6. 전투 기본 구조

### 6.1 기본 원칙

- 전투는 자동으로 진행한다.
- 한 행동은 하나 이상의 전투 이벤트를 발생시킬 수 있다.
- 행동 선택은 클래스와 스킬 설정을 기반으로 한다.
- 모든 확률 판정에는 해당 배틀의 난수 시드를 사용한다.
- 한 판은 짧게 끝나야 한다.
- 최대 턴을 넘기면 무승부 또는 결착 규칙을 적용한다.

### 6.2 목표 플레이 시간

| 항목 | 초기 목표 |
| --- | --- |
| 전투 시간 | 약 20~40초 |
| 로그 수 | 약 8~15개 주요 행동 |
| 로그 출력 간격 | 약 1.5~2초 |
| 최대 턴 | 미정 |
| 적정 동시 배틀 수 | 미정 |

### 6.3 전투 순서 초안

1. 캐릭터 스냅샷 생성
2. 전투용 능력치 계산
3. 선공 결정
4. 행동 캐릭터의 사용 가능한 스킬 확인
5. 스킬 선택
6. 명중·치명타·회피 등 확률 판정
7. 스킬 효과 적용
8. 전투 이벤트 생성
9. 이벤트에 맞는 메시지 출력
10. 전투 종료 조건 확인
11. 다음 턴 진행
12. 결과와 주요 이벤트 저장

## 7. 능력치 설계 방향

### 7.1 전투력

전투력은 전투의 중심 능력치로 사용한다. 다만 실제 전투력을 공격력이나 체력에 그대로 대입하면 전투력 차이가 곧 확정 승패가 될 수 있으므로 정규화가 필요하다.

가능한 활용:

- 최대 체력
- 기본 공격력
- 방어력
- 전투력 차이에 따른 소폭 보정

결정이 필요한 사항:

- 전투력을 전투용 수치로 변환하는 공식
- 전투력 차이가 승률에 미치는 최대 영향
- 매우 큰 전투력 격차에서도 역전 가능성을 둘지 여부

### 7.2 생활력

생활력은 부가적인 전투 요소로 사용할 예정이다. 구체적인 역할은 미정이다.

후보:

- 최대 체력 소폭 증가
- 턴마다 체력 회복
- 회복 스킬 효율 증가
- 상태 이상 저항
- 장기전 보너스

### 7.3 매력

매력도 부가적인 전투 요소로 사용할 예정이다. 구체적인 역할은 미정이다.

후보:

- 선공 확률
- 치명타 또는 회피 확률의 소폭 보정
- 유리한 특수 이벤트 발생
- 상대 행동 실패
- 관중 응원 효과
- 특별 전투 대사 출력

생활력과 매력을 합친 영향은 전투력과 클래스·스킬보다 작게 유지하는 방향을 우선 검토한다.

## 8. 클래스와 스킬

### 8.1 데이터 출처

- 클래스 데이터: Google Sheets의 클래스 테이블
- 스킬 데이터: 추후 Google Sheets에 추가할 직업별 스킬 테이블
- 캐릭터 능력치: 랭킹 검색 결과와 DB에 저장된 마지막 정상 데이터

Google Sheets는 기준 데이터의 원본으로 사용하고, 전투 시작 시마다 원격 조회하지 않는다. 갱신된 데이터를 검증한 뒤 봇 내부 캐시 또는 로컬 데이터로 교체하고, 실패하면 마지막 정상 데이터를 유지한다.

### 8.2 스킬 데이터 초안

| 필드 | 설명 | 상태 |
| --- | --- | --- |
| `SkillId` | 스킬 고유 ID | 필요 |
| `ClassId` | 소속 클래스 | 필요 |
| `Name` | 표시 이름 | 필요 |
| `Category` | 일반 공격, 액티브, 방어, 필살기 등 | 구체화 필요 |
| `SelectionWeight` | 자동 행동 선택 가중치 | 구체화 필요 |
| `Cooldown` | 재사용 대기 턴 | 구체화 필요 |
| `TargetType` | 자신, 적, 전체 등 | 구체화 필요 |
| `Effects` | 스킬 효과 목록 | 필요 |
| `Condition` | 체력 조건, 상태 조건 등 | 구체화 필요 |
| `MessageKey` | 출력 메시지 묶음 식별자 | 필요 |

### 8.3 스킬 효과 타입 초안

| 타입 | 설명 |
| --- | --- |
| `Damage` | 즉시 피해 |
| `Heal` | 체력 회복 |
| `Shield` | 일정 피해 흡수 |
| `StatBuff` | 공격·방어·속도 등 증가 |
| `StatDebuff` | 공격·방어·속도 등 감소 |
| `DamageOverTime` | 화상·중독 등 지속 피해 |
| `Stun` | 일정 턴 행동 불가 |
| `Counter` | 피격 시 반격 |
| `Cleanse` | 약화 효과 제거 |
| `Finisher` | 조건부 마무리 공격 |

한 스킬에는 여러 효과가 포함될 수 있다.

```text
화염 폭발
├── Damage
├── DamageOverTime
└── StatDebuff
```

따라서 스킬의 전투 효과와 출력 메시지 타입을 하나의 타입으로 합치지 않는다.

## 9. 전투 이벤트와 메시지

### 9.1 전투 이벤트 타입 초안

- `BattleStarted`
- `TurnStarted`
- `NormalAttackUsed`
- `SkillUsed`
- `AttackMissed`
- `AttackEvaded`
- `CriticalHit`
- `DamageDealt`
- `HealApplied`
- `ShieldApplied`
- `StatusApplied`
- `StatusRemoved`
- `CounterActivated`
- `CharacterDefeated`
- `BattleEnded`

### 9.2 메시지 생성 원칙

- 전투 계산과 메시지 생성을 분리한다.
- 전투 이벤트 하나에 여러 메시지 템플릿을 둘 수 있다.
- 동일한 행동이 반복되어도 표현이 지나치게 반복되지 않게 한다.
- 실제 수치는 이벤트 데이터에서 삽입한다.
- 초기 버전에서는 AI 생성 문장을 사용하지 않는다.

예시:

```text
{Actor}가 {Target}에게 일반 공격!
{Actor}의 공격이 {Target}을 향합니다!
{Actor}가 틈을 노려 공격합니다!
```

```text
치명타! {Damage}의 피해를 입혔습니다!
급소를 정확히 노렸습니다! {Damage}의 피해!
```

체력 상태 메시지 후보:

```text
{Target}은 아직 끄떡없습니다!
{Target}이 조금씩 밀리기 시작합니다.
{Target}의 상태가 심상치 않습니다.
{Target}은 간신히 버티고 있습니다.
```

체력 구간에 따라 메시지를 선택할 수 있다.

## 10. 승패와 밸런스

### 10.1 승리 조건 초안

- 상대 HP를 0 이하로 만들면 승리한다.
- 최대 턴 도달 시 남은 HP 비율로 승자를 결정하거나 무승부로 처리한다.
- 동시 처치 가능 여부는 구체화가 필요하다.

### 10.2 목표

- 전투력이 높은 캐릭터가 분명히 유리해야 한다.
- 전투력만 보고 결과를 확정적으로 예상할 수 없어야 한다.
- 클래스와 스킬의 차이가 전투 로그와 결과에 나타나야 한다.
- 무작위성 때문에 능력치 의미가 사라지지 않아야 한다.
- 특정 클래스가 모든 상황에서 항상 우세하지 않아야 한다.

### 10.3 밸런스 검증

구현 시 실제 Discord에서 반복 실행하기보다 전투 시뮬레이터 테스트를 제공한다.

예상 검증 항목:

- 동일 조건 10,000회 실행 시 클래스별 승률
- 전투력 격차별 승률
- 평균 전투 턴과 소요 시간
- 스킬별 선택률과 기여도
- 무승부 비율
- 특정 스킬의 무한 반복 또는 교착 여부
- 극단적인 전투력·생활력·매력 입력

## 11. 캐릭터 소유권

랭킹 검색만으로는 해당 Discord 사용자가 실제 캐릭터 소유자인지 증명할 수 없다.

검토할 정책:

| 정책 | 장점 | 단점 |
| --- | --- | --- |
| 같은 캐릭터 중복 허용 | 구현과 운영이 가장 단순함 | 캐릭터 정체성이 약해짐 |
| 캐릭터별 최초 한 명만 등록 | 캐릭터와 사용자가 1:1로 연결됨 | 선점과 사칭 가능 |
| 운영진 승인 | 길드 내부에서는 비교적 정확함 | 관리 부담 발생 |
| 게임 내 인증 정보 활용 | 소유권 확인 가능 | 게임/API가 지원해야 함 |

초기 권장안은 **길드 내부 사용을 전제로 캐릭터별 한 명만 등록하고, 분쟁 시 운영진이 등록을 해제하는 방식**이다. 확정 전 추가 논의가 필요하다.

## 12. 도전 정책

상대방을 지정하는 기능이므로 원하지 않는 반복 도전을 방지해야 한다.

초기 권장안:

- 상대방 수락 후에만 전투 시작
- 수락 제한 시간 적용
- 사용자별 도전 쿨다운 적용
- 동시에 하나의 배틀만 참가 가능
- 특정 사용자 차단 또는 배틀 신청 거부 설정 검토
- 봇 또는 탈퇴한 사용자에게 도전 불가

## 14. 재현성과 버전 관리

과거 전투 재현과 오류 분석을 위해 다음 정보를 저장한다.

- 난수 시드
- 참가자의 전투 시작 스냅샷
- 사용한 밸런스 데이터 버전
- 클래스·스킬 데이터 버전
- 전투 엔진 버전

밸런스나 Google Sheets 데이터가 변경되어도 과거 전투 결과 자체는 변경하지 않는다.

## 15. 오류와 복구

- 랭킹 수집 실패 시 마지막 정상 데이터를 사용할지 결정한다.
- 데이터가 너무 오래된 경우 배틀 시작을 막거나 경고한다.
- 스킬 데이터 로딩 실패가 전체 봇 시작을 막지 않게 한다.
- 전투 로그 전송 실패 시 재전송 또는 요약 결과 출력을 시도한다.
- 봇 재시작 시 진행 중 배틀은 초기 버전에서 취소 처리할 수 있다.
- DB 저장 실패 시 결과를 확정하기 전에 오류를 알린다.
- 전투 결과 저장과 전적 반영은 하나의 트랜잭션으로 처리한다.

## 16. MVP 제안

### 단계 1: 데이터와 전투 엔진

- 캐릭터 등록·조회·변경
- 랭킹 데이터 스냅샷 저장
- 클래스 데이터 로딩
- 전투력 기반 HP·공격력 계산
- 일반 공격
- 치명타와 회피
- HP와 승패
- 난수 시드 기반 전투 재현
- 전투 시뮬레이션 테스트

### 단계 2: Discord 배틀

- `/배틀 상대:@사용자`
- 수락·거절
- 전투 스레드 생성
- 시간차 전투 로그 출력
- 결과 요약
- 동시 배틀 상태 관리

### 단계 3: 클래스 스킬

- Google Sheets 스킬 테이블 추가
- 스킬과 효과 타입 파싱
- 스킬 선택 로직
- 쿨다운과 조건
- 버프·디버프·상태 이상
- 타입별 메시지 템플릿

### 단계 4: 기록

- 전적 저장
- 최근 배틀 조회
- 캐릭터별 승패
- 클래스별 통계
- 재대결

생활력과 매력의 전투 효과는 단계 1에서 확정하지 않아도 되며, 전투력과 스킬 기반 MVP가 안정된 뒤 추가하는 것을 우선 검토한다.

## 17. 구체화가 필요한 항목

### P0: 구현 전에 반드시 결정

1. **놀이터 구현 방식**
   - 배틀별 스레드, 고정 채널, 임시 채널 중 선택

2. **캐릭터 소유권 정책**
   - 중복 등록 허용 여부
   - 사칭·선점 발생 시 처리 방법

3. **랭킹 데이터 갱신 정책**
   - 등록 시에만 조회할지
   - 배틀 전에 갱신할지
   - 캐시 유효 시간을 둘지
   - 마지막 정상 데이터가 오래됐을 때 배틀을 허용할지

4. **전투력 변환 공식**
   - HP·공격력·방어력 계산
   - 전투력 차이와 목표 승률
   - 극단적인 격차 처리

5. **기본 전투 규칙**
   - 선공 결정
   - 명중·회피·치명타
   - 최대 턴
   - 무승부 및 동시 처치 처리

6. **전투 진행 속도**
   - 로그 간격
   - 목표 턴 수
   - 전투 한 판의 최대 시간

7. **도전 수락 정책**
   - 수락 필수 여부
   - 수락 제한 시간
   - 도전 쿨다운

### P1: 클래스 스킬 추가 전에 결정

1. Google Sheets 스킬 테이블의 정확한 열 구조
2. 스킬 효과 타입 목록
3. 복합 효과 표현 방식
4. 스킬 자동 선택 방식
5. 쿨다운 단위
6. 사용 조건 표현 방식
7. 버프·디버프 중첩 규칙
8. 상태 이상 저항과 해제 규칙
9. 클래스별 기본 공격 차별화 여부
10. 스킬 및 메시지 데이터 버전 관리 방식

### P2: MVP 이후 결정

1. 생활력의 전투 효과
2. 매력의 전투 효과
3. 전적 공개 범위
4. 랭킹과 시즌 도입 여부

## 18. 다음 기획 순서

다음 논의에서는 아래 순서로 구체화한다.

1. 놀이터가 실제 Discord에서 어떻게 보이고 동작할지 결정한다.
2. 캐릭터 등록과 갱신 정책을 확정한다.
3. 전투력 기반의 최소 전투 공식을 만든다.
4. 일반 공격만 사용하는 프로토타입 전투를 시뮬레이션한다.
5. 목표 승률과 전투 시간을 기준으로 공식을 조정한다.
6. Google Sheets 스킬 테이블 구조를 확정한다.
7. 클래스별 스킬을 추가하고 전투 로그의 재미를 검증한다.
