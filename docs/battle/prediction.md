# 배틀 예측 기획서

> 문서 상태: 구현 완료  
> 최종 갱신: 2026-09-28  
> 관련 문서: [배틀 기획서](README.md), [마물 퇴치 증표 기획서](../currency/monster-hunt-token.md), [출석 기획서](../attendance/README.md)

## 1. 개요

배틀 예측은 기존 `/배틀`의 30초 준비 시간 동안 서버 사용자(배틀 참가자 포함)가 승자를 선택하고 `마물 퇴치 증표`를 거는 놀이 기능이다. 적중자는 승리 진영에 걸린 비율에 따라 전체 판돈을 나눠 받는다.

예측은 배틀에 영향을 주지 않는다. 전투 스탯, 스킬, AI, 난수와 결과는 예측 참여 여부와 금액에 관계없이 기존 배틀 규칙대로 결정된다. 전투 시뮬레이션은 예측이 마감된 뒤에 시작하므로 베팅하는 동안에는 결과가 정해져 있지 않다.

### 핵심 한 줄

> 자동 배틀이 시작되기 전 30초 동안 서버 사용자들이 마물 퇴치 증표를 걸고 승자를 함께 예상하는 짧은 관전 놀이.

## 2. 참여 대상

- 배틀이 진행되는 Discord 서버의 사용자만 참여할 수 있다.
- 도전자와 상대도 자신의 배틀을 예측할 수 있다. 어느 쪽에 걸지도 자유다. 전투 변수가 많아 결과를 조작하거나 확신할 수 없기 때문이다(2026-09-29 사용자 결정).
- 서버마다 잔액이 다르므로 현재 서버의 마물 퇴치 증표만 사용할 수 있다.
- 캐릭터를 등록하지 않은 관전자도 참여할 수 있다.
- `/모의배틀`에는 예측을 열지 않는다.

## 3. 사용자 흐름

1. `/배틀` 신청이 정상적으로 성립하고 배틀 스레드가 생긴다.
2. 스레드의 준비 메시지(30초 준비 안내)에 예측 버튼이 함께 붙는다. 원래 채널에는 예측 안내나 결과를 올리지 않는다.
3. 참여자는 진영별 금액 버튼을 누른다. 버튼 한 번이 곧 베팅이다.
4. 같은 진영의 버튼을 다시 누르면 금액이 더해진다.
5. 준비 시간이 끝나면 예측을 마감하고 버튼을 없앤 뒤, 진영별로 걸린 비율(퍼센트와 게이지)을 보여주고 전투를 시작한다. 실제 수량은 공개하지 않는다.
6. 배틀이 끝나면 결과에 따라 증표를 정산하고 스레드에 정산 결과를 남긴다. 무효 조건이면 증표는 오가지 않는다.

버튼 배치:

```text
[종잇장 승리] [(증표 이모지)10개] [(증표 이모지)50개] [(증표 이모지)100개]   ← 파란 버튼(도전자)
[핏피 승리]   [(증표 이모지)10개] [(증표 이모지)50개] [(증표 이모지)100개]   ← 빨간 버튼(상대)
```

맨 앞의 진영 이름 버튼은 누를 수 없는 표시용이다. 색은 배틀 로그와 같게 도전자 파랑, 상대 빨강이다.

## 4. 참여 규칙

- 사용자 한 명은 한 예측에서 한 진영에만 걸 수 있다. 진영 변경과 취소는 할 수 없다.
- 같은 진영에는 여러 번 눌러 금액을 더할 수 있다.
- 한 예측에 거는 누적 금액은 `min(고정 상한, 가방 잔액 × 잔액 비율 상한)`(내림)을 넘을 수 없다. 넘는 버튼은 거부하고 현재 누적액과 상한을 알려준다.
- 버튼 금액, 비율 상한, 고정 상한, 최소 참여 인원은 `증표규칙` 시트에서 관리한다.
- 마감 시점에 참여자가 최소 인원보다 적거나 한쪽 진영에만 베팅이 있으면 예측은 무효다. 배틀은 그대로 진행한다.

| ID | 자료형 | 값 | 범위 | 의미 |
| --- | --- | --- | --- | --- |
| `prediction_bet_amounts` | 정수목록 | `10\|50\|100` | 1~10000, 최대 4개 | 버튼 금액 |
| `prediction_max_balance_ratio` | 실수 | 0.5 | 0.01~1 | 가방 대비 한 예측 누적 상한 |
| `prediction_max_bet_amount` | 정수 | 500 | 1~100000 | 한 예측 누적 고정 상한 |
| `prediction_min_predictor_count` | 정수 | 2 | 2~100 | 예측이 성립하는 최소 인원 |

행이 없거나 잘못되면 위 값이 코드 기본값으로 쓰인다(`Prediction/PredictionRules.cs`).

## 5. 증표 차감 시점

증표는 **걸 때가 아니라 정산할 때** 움직인다. 걸 때는 예측 기록만 남기고, 배틀이 정상 종료되어 승자가 정해졌을 때 한 트랜잭션에서 모든 참여자의 차감과 배당을 함께 반영한다.

- 한 서버에서는 배틀이 동시에 하나만 진행되고, 증표 사용처는 예측뿐이며, 잔액은 서버별로 분리되므로 베팅부터 정산 사이에 잔액이 줄어들 방법이 없다.
- 그래도 안전을 위해 베팅할 때 같은 서버의 정산되지 않은 다른 예측에 건 금액을 잔액에서 빼고 계산한다.
- 무효·강제 종료·오류·재시작 때는 증표가 움직인 적이 없으므로 환불 거래 없이 예측만 취소 처리한다.
- 정산 중 잔액이 모자란 사람이 있으면(정상적으로는 발생하지 않음) 모든 변경을 되돌리고 예측을 취소한다.
- 나중에 예측 외의 증표 사용처가 생기면, 그 기능도 정산되지 않은 예측 금액을 빼고 잔액을 판단해야 한다.

## 6. 배당 규칙

트위치식 공동 배당 구조를 사용한다. 수수료는 없다.

```text
개인 배당금 = 전체 판돈 × 개인의 승리 진영 베팅액 ÷ 승리 진영 총베팅액
```

예시:

- A 진영 총베팅: 300개
- B 진영 총베팅: 200개
- 전체 판돈: 500개
- A가 승리하고 어떤 사용자가 A에 60개를 걸었다면 `500 × 60 ÷ 300 = 100`을 받는다. 순이익은 40개다.

정수 재화의 나머지는 다음 순서로 배분한다.

1. 모든 배당을 내림하여 계산한다.
2. 소수점 나머지가 큰 사용자부터 1개씩 지급한다.
3. 소수점 나머지가 같으면 베팅액이 큰 사용자를 우선한다.
4. 베팅액도 같으면 먼저 베팅한 사용자를 우선한다.

지급 총합은 항상 전체 판돈과 정확히 같다.

## 7. 결과와 무효

### 정상 정산

- 모든 참여자에게 건 금액을 차감(`prediction_bet`)하고, 승리 진영 참여자에게 배당금을 지급(`prediction_payout`)한다. 두 거래는 한 트랜잭션이다.
- 정산 결과는 배틀 스레드에 종료 메시지 다음으로 남긴다. 맞힌 사람과 받은 수량을 멘션 알림 없이 보여준다.

### 무효(증표 변동 없음)

- 무승부
- `/배틀종료`로 강제 종료
- 배틀 진행 중 오류
- 재시작으로 배틀이 끊김
- 최소 참여자 수 미달
- 한쪽 진영에만 베팅 존재
- 정산 중 잔액 부족

예측 오류는 배틀 결과를 바꾸거나 배틀 자체를 실패시키지 않는다. 예측을 열지 못하면 버튼 없이 배틀만 진행하고, 정산할 수 없으면 무효로 처리한다. `prediction_refund` 사유는 이 방식에서 쓰지 않는다.

## 8. 데이터 설계

예측 ID와 배틀 ID는 배틀 스레드 ID를 그대로 쓴다. 이미 고유하고, 예측을 여는 시점에 만들어져 있으며, 한 배틀에 예측은 하나다.

`battle_predictions`

| 필드 | 의미 |
| --- | --- |
| `prediction_id` | 예측 ID(배틀 스레드 ID) |
| `guild_id` | Discord 서버 ID |
| `challenger_user_id` / `opponent_user_id` | 도전자·상대 사용자 ID |
| `challenger_name` / `opponent_name` | 버튼·안내에 쓰는 캐릭터 이름 |
| `status` | `open`, `locked`, `resolved`, `cancelled` |
| `cancel_reason` | 무효 사유 |
| `winning_side` | 승리 진영. 무효면 없음 |
| `rules_snapshot` | 예측을 열 때 고정한 규칙(JSON) |
| `opened_at` / `locked_at` / `resolved_at` | 시작·마감·정산(또는 취소) 시각 |

`battle_prediction_entries`

| 필드 | 의미 |
| --- | --- |
| `prediction_id` | 예측 ID |
| `guild_id` | Discord 서버 ID |
| `user_id` | 참여자 ID |
| `selected_side` | 선택 진영 |
| `amount` | 누적 베팅액 |
| `payout_amount` | 정산 지급액(정산 전·무효는 없음) |
| `created_at` / `updated_at` / `settled_at` | 첫 참여·마지막 추가·정산 시각 |

`(prediction_id, user_id)`가 기본 키다. 원장의 참조 ID는 `battle-prediction:{prediction_id}`다.

## 9. 규칙 스냅샷

- 예측을 열 때 현재 유효한 `증표규칙` 값을 `rules_snapshot`에 고정한다.
- 예측이 열린 뒤 시트 값이 바뀌어도 진행 중인 예측에는 영향을 주지 않는다.
- 시트가 유효하지 않으면 마지막 정상 규칙을, 그마저 없으면 코드 기본값을 사용한다.

## 10. 동시성·재시작·멱등성

- 베팅 판정(상태·참가자·진영·상한)과 기록은 하나의 DB 트랜잭션으로 처리한다.
- 마감(`locked`) 이후 도착한 버튼은 DB 상태로 거부한다.
- 정산과 무효 처리는 `open`·`locked` 상태에서만 한 번 적용되고, 다시 호출하면 이미 처리된 결과를 돌려준다. 원장도 `(사유, 참조 ID)` 유일 키로 중복 반영을 막는다.
- 봇 시작 시 `open`·`locked` 상태의 예측을 모두 `cancelled`(재시작)로 바꾼다. 증표는 움직이지 않았으므로 환불할 것이 없다.
- 배틀 로그 메시지 전송 실패와 예측 정산 실패를 분리한다.

## 11. 메시지

준비 메시지(스레드):

```text
⚔️ @도전자(종잇장 · 클래스) vs @상대(핏피 · 클래스)
30초 뒤 전투를 시작합니다. 준비하세요!

🔮 승부 예측: 이길 쪽의 버튼을 눌러 마물 퇴치 증표를 걸어주세요. 같은 쪽을 다시 누르면 더 걸 수 있어요.
맞히면 전체 판돈을 건 비율대로 나눠 받아요. 증표는 배틀이 끝난 뒤 정산돼요. 배틀 참가자도 예측할 수 있어요.
```

베팅 응답(본인만):

```text
종잇장의 승리에 마물 퇴치 증표 50개를 걸었어요. (누적 (증표 이모지)60개)
```

마감(전투 시작):

```text
🔮 예측 마감
🟦🟦🟦🟦🟦🟦🟥🟥🟥🟥
종잇장 62% · 핏피 38%
```

게이지는 버튼 색과 같게 도전자 🟦·상대 🟥 네모 이모지 10칸(한 칸 10%)이다. Discord에 게이지 컴포넌트가 없어 이모지로 그리며, 모바일에서도 한 줄에 들어가도록 10칸으로 한다. 양쪽 모두 걸렸으면 적은 쪽도 최소 1칸은 보이게 한다.

정산:

```text
🔮 종잇장의 승리를 맞힌 2명이 판돈 (증표 이모지)500개를 나눠 받았어요.
• @관전자1 (증표 이모지)100개
• @관전자2 (증표 이모지)400개
```

공개 범위: 정산 메시지에는 트위치 예측 결과처럼 적중자별로 받은 총액(원금 포함) 하나만 쓴다. 건 양·순이익·잔액은 쓰지 않는다. 건 양을 함께 보여주면 보유량이 그 정도라고 느껴질 수 있기 때문이다(2026-09-29 사용자 결정). 틀린 쪽은 인원만 쓴다. 마감 메시지에는 걸린 수량 대신 비율과 게이지만 쓴다. 잔액과 누적 상한은 버튼을 누른 사람에게만 보이는 응답에서만 보여준다. 전체 원칙은 [마물 퇴치 증표 기획서 3.1](../currency/monster-hunt-token.md#31-보유량-공개-범위)을 따른다.

수량만 보여주는 요약·버튼에는 전용 이모지를 사용하고, 몰리가 문장으로 설명할 때는 풀네임을 사용한다.

## 12. 초기 범위에서 제외할 것

- 모의배틀 예측
- 진영 변경·취소, 금액 직접 입력
- 운영 수수료
- 배율 고정식 베팅
- 예측 전적·랭킹·연승 보상
- 증표가 아닌 다른 재화 사용
- 예측 결과가 전투에 주는 효과
- 원래 채널에 예측 결과 알림
- 재시작으로 취소된 예측을 스레드에 안내

## 13. 완료 조건

- 배틀 참가자를 포함한 서버 사용자가 30초 안에 버튼만으로 참여할 수 있다.
- 반대 진영 베팅과 상한 초과가 차단된다.
- 예측이 전투 계산과 결과에 전혀 영향을 주지 않는다.
- 정상 종료 시 전체 판돈이 오차 없이 승리 진영에 배분된다.
- 무승부·강제 종료·오류·재시작 상황에서 증표가 움직이지 않는다.
- 모든 차감·배당이 거래 원장에 남고 중복 처리되지 않는다.
- 이름 없는 수량 표기가 몰리봇 전용 증표 이모지를 사용한다.
