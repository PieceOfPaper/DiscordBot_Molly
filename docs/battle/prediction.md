# 배틀 예측 기획서

> 문서 상태: 구현 전 기획 초안  
> 최종 갱신: 2026-09-28  
> 관련 문서: [배틀 기획서](README.md), [마물 퇴치 증표 기획서](../currency/monster-hunt-token.md), [출석 기획서](../attendance/README.md)

## 1. 개요

배틀 예측은 기존 `/배틀`의 30초 준비 시간 동안 관전자가 승자를 선택하고 `마물 퇴치 증표`를 거는 놀이 기능이다. 적중자는 승리 진영에 걸린 비율에 따라 전체 판돈을 나눠 받는다.

예측은 배틀에 영향을 주지 않는다. 전투 스탯, 스킬, AI, 난수와 결과는 예측 참여 여부와 금액에 관계없이 기존 배틀 규칙대로 결정된다.

### 핵심 한 줄

> 자동 배틀이 시작되기 전 30초 동안 관전자들이 마물 퇴치 증표를 걸고 승자를 함께 예상하는 짧은 관전 놀이.

## 2. 참여 대상

- 배틀이 진행되는 Discord 서버의 사용자만 참여할 수 있다.
- 도전자와 상대는 자신의 배틀에 참여할 수 없다.
- 서버마다 잔액이 다르므로 현재 서버의 마물 퇴치 증표만 사용할 수 있다.
- 봇과 시스템 계정은 참여할 수 없다.
- 캐릭터를 등록하지 않은 관전자도 참여할 수 있다.

## 3. 사용자 흐름

1. `/배틀` 신청이 정상적으로 성립한다.
2. 기존 30초 준비 시간과 함께 예측이 열린다.
3. 관전자는 도전자 또는 상대를 선택한다.
4. `10개`, `50개`, `100개`, `직접 입력` 등의 금액을 고른다.
5. 유효성 검사를 통과하면 해당 금액을 즉시 차감하여 예측 판돈으로 맡긴다.
6. 준비 시간이 끝나기 전에 예측을 잠그고 배틀을 시작한다.
7. 정상 종료된 배틀 결과에 따라 배당하거나, 무효 조건이면 전액 환불한다.

버튼처럼 재화 이름을 생략하는 금액 표시는 전용 이모지를 붙여 `(증표 이모지)10개` 형식으로 출력한다.

## 4. 참여 규칙

- 사용자 한 명은 예측 하나에 한 번만 참여할 수 있다.
- 제출 후 진영 변경, 금액 추가, 일부 취소는 할 수 없다.
- 보유량보다 많은 금액을 걸 수 없다.
- 최소 금액, 금액 단위, 빠른 선택 금액, 최대 금액은 `증표규칙` 시트에서 관리한다.
- 최대 베팅액은 고정 상한과 현재 잔액 비율 상한 중 더 작은 값으로 제한하는 방향을 사용한다.
- 예측 참여자가 최소 인원보다 적으면 배틀은 그대로 진행하고 판돈만 전액 환불한다.
- 한쪽 진영에만 베팅이 모인 경우에도 판돈을 전액 환불한다.

초기 제안값은 다음과 같으며 구현 전에 다시 확정한다.

| 항목 | 제안값 |
| --- | ---: |
| 최소 금액 | 10개 |
| 베팅 단위 | 10개 |
| 빠른 선택 | 10개 / 50개 / 100개 |
| 잔액 비율 상한 | 50% |
| 고정 금액 상한 | 500개 |
| 최소 참여자 | 2명 |

## 5. 배당 규칙

트위치식 공동 배당 구조를 사용한다. 수수료는 없다.

```text
개인 배당금 = 전체 판돈 × 개인의 승리 진영 베팅액 ÷ 승리 진영 총베팅액
```

예시:

- A 진영 총베팅: 300개
- B 진영 총베팅: 200개
- 전체 판돈: 500개
- A가 승리하고 어떤 사용자가 A에 60개를 걸었다면 `500 × 60 ÷ 300`을 기준으로 배당한다.

정수 재화의 나머지는 다음 순서로 배분한다.

1. 모든 배당을 내림하여 계산한다.
2. 소수점 나머지가 큰 사용자부터 1개씩 지급한다.
3. 소수점 나머지가 같으면 베팅액이 큰 사용자를 우선한다.
4. 베팅액도 같으면 먼저 베팅한 사용자를 우선한다.

지급 총합은 항상 전체 판돈과 정확히 같아야 한다.

## 6. 결과와 환불

### 정상 정산

- 승리 진영 참가자에게 계산된 배당금을 지급한다.
- 패배 진영의 판돈은 별도로 반환하지 않는다.
- 정산 결과는 배틀 결과 메시지에 함께 표시한다.

### 전액 환불

다음 상황에서는 참여자 전원에게 맡긴 금액을 그대로 돌려준다.

- 무승부
- `/배틀종료`로 강제 종료
- 배틀 생성 또는 진행 중 오류
- 재시작 후 신뢰할 수 있는 결과를 확인할 수 없음
- 최소 참여자 수 미달
- 한쪽 진영에만 베팅 존재
- 배틀 취소

예측 정산 오류는 배틀 결과를 변경하거나 배틀 자체를 실패시켜서는 안 된다. 정산할 수 없다면 안전하게 환불하고 배틀은 기존 규칙대로 마친다.

## 7. 데이터 설계

`battle_predictions`

| 필드 | 의미 |
| --- | --- |
| `prediction_id` | 예측 ID |
| `guild_id` | Discord 서버 ID |
| `battle_id` | 배틀 ID |
| `challenger_user_id` | 도전자 사용자 ID |
| `opponent_user_id` | 상대 사용자 ID |
| `status` | `open`, `locked`, `resolved`, `refunded` |
| `opened_at` | 예측 시작 시각 |
| `locked_at` | 예측 마감 시각 |
| `resolved_at` | 정산 완료 시각 |
| `winning_side` | 승리 진영. 환불이면 없음 |
| `rules_snapshot` | 해당 예측에 고정한 규칙 |

`battle_prediction_entries`

| 필드 | 의미 |
| --- | --- |
| `prediction_id` | 예측 ID |
| `guild_id` | Discord 서버 ID |
| `user_id` | 참여자 ID |
| `selected_side` | 선택 진영 |
| `amount` | 베팅액 |
| `payout_amount` | 정산 지급액 |
| `created_at` | 참여 시각 |
| `settled_at` | 정산 시각 |

`(prediction_id, user_id)`를 유일 키로 사용한다.

## 8. 규칙 스냅샷

- 예측을 열 때 현재 유효한 `증표규칙` 값을 복사하여 `rules_snapshot`에 고정한다.
- 예측이 열린 뒤 시트 값이 바뀌어도 진행 중인 예측에는 영향을 주지 않는다.
- 새 값은 다음에 열리는 예측부터 적용한다.
- 시트가 유효하지 않으면 마지막 정상 규칙을 사용한다.

관련 규칙 ID 후보:

- `prediction_min_bet_amount`
- `prediction_bet_unit`
- `prediction_quick_bet_1`
- `prediction_quick_bet_2`
- `prediction_quick_bet_3`
- `prediction_max_balance_ratio`
- `prediction_max_bet_amount`
- `prediction_min_predictor_count`

## 9. 동시성·재시작·멱등성

- 베팅 등록과 잔액 차감은 하나의 DB 트랜잭션으로 처리한다.
- 잠금 이후 도착한 요청은 받지 않는다.
- 정산과 각 사용자 지급은 여러 번 호출되어도 한 번만 적용되어야 한다.
- 봇 재시작 시 `open` 또는 `locked` 상태의 예측을 조회한다.
- 신뢰할 수 있는 배틀 결과가 저장되어 있으면 정상 정산하고, 아니면 환불한다.
- 환불 역시 원장 `reference_id`로 중복 처리를 막는다.
- 배틀 로그 메시지 전송 실패와 예측 정산 실패를 분리하여 한쪽 오류가 다른 쪽을 확산시키지 않게 한다.

## 10. 메시지 방향

예측 시작:

```text
🔮 배틀 승부 예측
종잇장 vs 핏피
30초 안에 승자를 선택해주세요.

[종잇장] [핏피]
[(증표 이모지)10개] [(증표 이모지)50개] [(증표 이모지)100개] [직접 입력]
```

예측 성공:

```text
종잇장의 승리에 마물 퇴치 증표 50개를 걸었습니다.
```

정산:

```text
종잇장의 승리를 맞혔습니다!
마물 퇴치 증표 83개를 받았습니다.
```

수량만 보여주는 요약·버튼에는 전용 이모지를 사용하고, 몰리가 문장으로 설명할 때는 풀네임을 사용한다.

## 11. 초기 범위에서 제외할 것

- 모의배틀 예측
- 배틀 참가자의 자기 경기 베팅
- 베팅 변경·추가·취소
- 운영 수수료
- 배율 고정식 베팅
- 예측 전적·랭킹·연승 보상
- 증표가 아닌 다른 재화 사용
- 예측 결과가 전투에 주는 효과

## 12. 구현 전 확인 사항

- 베팅 관련 제안 수치의 최종 확정
- 배틀 준비 메시지와 예측 UI를 합칠지 별도 메시지로 둘지
- 직접 입력을 모달로 받을지 다른 상호작용으로 받을지
- 최소 참가 인원과 양쪽 진영 참여 조건의 최종 문구
- 배틀 결과가 DB에 확정되는 정확한 시점과 재시작 복구 기준

## 13. 완료 조건

- 배틀 참가자를 제외한 관전자가 30초 안에 쉽게 참여할 수 있다.
- 같은 사용자의 중복 참여와 잔액 초과 사용이 차단된다.
- 예측이 전투 계산과 결과에 전혀 영향을 주지 않는다.
- 정상 종료 시 전체 판돈이 오차 없이 승리 진영에 배분된다.
- 취소·무승부·오류·재시작 상황에서 안전하게 환불된다.
- 모든 차감·배당·환불이 거래 원장에 남고 중복 처리되지 않는다.
- 이름 없는 수량 표기가 몰리봇 전용 증표 이모지를 사용한다.
