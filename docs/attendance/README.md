# 출석 기획서

> 문서 상태: 구현 전 기획 확정안  
> 최종 갱신: 2026-09-28  
> 관련 문서: [마물 퇴치 증표 기획서](../currency/monster-hunt-token.md), [배틀 예측 기획서](../battle/prediction.md)

## 1. 개요

출석은 서버에 설치된 출석부 메시지의 버튼을 하루 한 번 누르고 `마물 퇴치 증표`를 받는 기능이다. 별도의 일일 과제나 연속 출석 보너스 없이, 몰리에 들를 가벼운 계기와 배틀 예측용 재화의 기본 공급처만 제공한다.

### 핵심 한 줄

> 매일 오전 6시에 갱신되는 한 장의 출석부에서 버튼 한 번으로 출석하고 마물 퇴치 증표를 받는다.

## 2. 등록

명령어:

```text
/출석부등록
```

- 서버 관리 권한이 있는 사용자만 실행할 수 있다.
- 명령을 실행한 채널을 해당 서버의 출석부 채널로 등록한다.
- 서버마다 출석부 채널 하나와 활성 메시지 하나만 둔다.
- 이미 등록된 서버에서 다른 채널에 다시 등록하면 기존 출석부를 비활성화하고 새 채널에 대체 메시지를 만든다.
- Discord 메시지는 채널 간 이동할 수 없으므로 채널 변경 시에는 새 메시지가 필요하다.

## 3. 출석일과 초기화

- 기준 시간대는 `Asia/Seoul`이다.
- 매일 **오전 6시(KST)**에 새 출석일이 시작된다.
- 논리 출석일은 `(현재 KST 시각 - 6시간)의 날짜`로 계산한다.
- 예를 들어 9월 29일 오전 2시는 9월 28일 출석으로 처리한다.
- 봇이 오전 6시에 꺼져 있었더라도 다음 시작 또는 상호작용 시 현재 논리 출석일을 계산해 즉시 갱신한다.

## 4. 출석부 메시지

출석부는 날짜마다 새 메시지를 만들지 않고 **같은 Discord 메시지 하나를 계속 수정**한다.

예시:

```text
📅 2026년 9월 28일 월요일 출석부

오늘 몰리에 들른 사람은 출석해주세요!

출석 인원: 3명
1. 종잇장
2. 핏피
3. 몰리친구

매일 오전 6시에 초기화됩니다.

[출석]
```

- 날짜, 요일, 출석 인원과 이름 목록을 한 메시지에서 갱신한다.
- 이름은 멘션이 아닌 일반 텍스트로 표시하여 불필요한 알림을 만들지 않는다.
- 동일한 표시 이름이 있어도 실제 판정은 Discord 사용자 ID로 한다.
- 메시지 길이 제한을 넘으면 목록 일부만 표시하고 전체 인원 수는 유지한다. 전체 목록 조회 기능은 후속 범위로 둔다.

## 5. 버튼 처리

1. 사용자가 `출석` 버튼을 누른다.
2. 현재 서버와 현재 논리 출석일을 계산한다.
3. 이미 같은 출석일에 출석했는지 확인한다.
4. 처음이면 출석 기록과 마물 퇴치 증표 지급을 하나의 DB 트랜잭션으로 저장한다.
5. 출석부 메시지를 최신 명단으로 수정한다.
6. 사용자에게 지급 결과를 본인만 보이도록 안내한다.

예시 응답:

```text
출석했습니다! 마물 퇴치 증표 50개를 받았습니다.
```

실제 지급량은 `증표규칙` 시트의 유효한 현재 값을 사용한다. 이름을 생략하고 수량만 표시하는 보조 UI가 있다면 [증표 표기 규칙](../currency/monster-hunt-token.md#2-명칭과-표시-규칙)에 따라 전용 이모지를 붙인다.

이미 출석한 사용자는 다시 지급받을 수 없다.

```text
오늘은 이미 출석했습니다. 다음 출석은 오전 6시부터 가능합니다.
```

## 6. 영속성과 복구

서버별로 최소 다음 정보를 저장한다.

`attendance_settings`

| 필드 | 의미 |
| --- | --- |
| `guild_id` | Discord 서버 ID |
| `channel_id` | 출석부 채널 ID |
| `message_id` | 계속 수정할 출석부 메시지 ID |
| `current_attendance_date` | 현재 메시지에 표시한 논리 출석일 |
| `enabled` | 사용 여부 |
| `created_at` | 등록 시각 |
| `updated_at` | 마지막 변경 시각 |

`attendance_entries`

| 필드 | 의미 |
| --- | --- |
| `guild_id` | Discord 서버 ID |
| `attendance_date` | 논리 출석일 |
| `user_id` | Discord 사용자 ID |
| `display_name` | 출석 당시 표시 이름 |
| `reward_amount` | 실제 지급량 |
| `created_at` | 출석 시각 |

`(guild_id, attendance_date, user_id)`를 유일 키로 사용한다.

### 재시작

- 버튼 custom ID는 메모리 상태에 의존하지 않는 고정 형식(예: `attendance:check_in`)을 사용한다.
- 봇 시작 시 DB에서 활성 출석부를 읽고 저장된 메시지를 다시 연결한다.
- 현재 논리 출석일이 저장값과 다르면 같은 메시지를 새 날짜와 빈 명단으로 갱신한다.

### 메시지·채널 삭제

- 메시지만 삭제된 경우 같은 채널에 새 출석부를 만들고 `message_id`를 교체한다. DB의 당일 출석 기록은 유지한다.
- 채널이 삭제되었거나 접근할 수 없으면 설정을 비활성화하고 관리자가 `/출석부등록`을 다시 실행하도록 안내한다.

## 7. 동시성 및 실패 처리

- 출석 기록 생성과 증표 지급은 반드시 같은 DB 트랜잭션에서 성공하거나 함께 실패한다.
- 중복 버튼 클릭과 여러 봇 작업의 동시 처리를 DB 유일 키로 차단한다.
- DB 저장은 성공했지만 메시지 수정이 실패한 경우 보상을 되돌리지 않는다. 이후 메시지 복구 작업이 DB를 기준으로 다시 그린다.
- 메시지 수정에 실패했다고 버튼 요청을 재처리하여 중복 지급하지 않는다.
- Google Sheets 규칙을 읽을 수 없으면 마지막 정상 규칙을 사용한다.

## 8. Google Sheets 규칙

`증표규칙` 시트에서 다음 값을 관리할 예정이다.

- `attendance_reset_hour_kst`
- `attendance_reward_amount`

출석 버튼을 누르는 시점의 유효한 규칙을 적용하고, 실제 지급량을 출석 기록과 거래 원장에 함께 남긴다.

## 9. 초기 범위에서 제외할 것

- 연속 출석 보너스
- 개근 보상
- 출석 순위
- 소급 출석
- 출석 취소
- 별도의 일일 과제
- 출석자 전체 목록을 위한 별도 페이지
- 하루 여러 차례의 보상

## 10. 완료 조건

- 서버마다 출석부 하나만 활성화된다.
- 오전 6시 KST를 기준으로 날짜가 정확히 바뀐다.
- 날짜가 바뀌어도 같은 Discord 메시지를 계속 사용한다.
- 봇 재시작 후에도 기존 메시지와 버튼이 작동한다.
- 같은 사용자는 서버별·출석일별 한 번만 보상받는다.
- 출석 기록과 마물 퇴치 증표 지급이 원자적으로 처리된다.
- 삭제된 메시지는 당일 기록을 잃지 않고 복구된다.
