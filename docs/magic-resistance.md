# 마도저항 확인 기획서

> 상태: 구현  
> 기준일: 2026-10-19 (기준값 적용일, 지옥4 개방일)  
> 구현: `MagicResistance/`(게임 데이터 기준값·계산), `Commands/MagicResistanceCommand.cs`(Discord 임베드)  
> 갱신: 2026-10-31 기준값을 코드 상수에서 게임 데이터 저장소(언팩 데이터)로 교체

## 기능명

`/마도저항확인`

## 분류

편의

## 해결하려는 문제

룬다 어비스 지옥 난이도마다 마도 압력이 달라, 지금 마도저항으로 어느 난이도에서 피해가 얼마나 늘고 줄어드는지 직접 계산하기 번거롭다. 게임 안에서는 난이도별 증감률을 한 화면에서 비교할 수 없다.

## Discord에서 제공하는 이점

수치 하나만 입력하면 네 난이도의 주는·받는 피해 증감을 한 번에 비교해 길드원과 바로 공유할 수 있다.

## 핵심 사용자 흐름

1. `/마도저항확인 마도저항:7200` 실행
2. 몰리가 지옥 난이도별(현재 지옥1~4) 주는 피해·받는 피해 증감률과 입장 기준 미달 여부를 임베드 하나로 응답(채널에 공개)

## 입력

- `마도저항`: 필수 정수, 0 이상(`MinValue(0)`).
- 캐릭터 정보를 조회하지 않고 입력값으로만 계산한다. 사용자 등록·DB 저장·외부 API 호출 없음.

## 기준값

| 콘텐츠 | 필요 마도저항 | 마도 압력 | 출처 |
|---|---:|---:|---|
| 룬다 어비스 지옥1 | 3,500 | 4,400 | 공식 공지 미확인. [나무위키 룬다 어비스](https://namu.wiki/w/%EB%A7%88%EB%B9%84%EB%85%B8%EA%B8%B0%20%EB%AA%A8%EB%B0%94%EC%9D%BC/%EC%96%B4%EB%B9%84%EC%8A%A4/%EB%A3%AC%EB%8B%A4) 표 |
| 룬다 어비스 지옥2 | 6,000 | 6,600 | [9/17 업데이트](https://mabinogimobile.nexon.com/News/Update/3545062): 6,500/7,200에서 조정 |
| 룬다 어비스 지옥3 | 7,200 | 7,800 | [9/17 업데이트](https://mabinogimobile.nexon.com/News/Update/3545062), 9/21 개방 |
| 룬다 어비스 지옥4 | 8,500 | 9,000 | [10/15 업데이트](https://mabinogimobile.nexon.com/News/Update/3563175), 10/19 개방 |

- 필요 마도저항은 **입장 조건**, 마도 압력은 **피해 증감 계산 기준**이다.
- 위 표는 기획 당시 공지로 확인한 값이다. 지금은 게임 데이터 저장소([연동 문서](unpack-repo.md))의 값을 쓰며, 2026-10-31 저장소 기준 네 난이도 모두 위 표와 같다(지옥1의 3,500/4,400도 게임 데이터로 확인).
  - `AbyssDungeon.RequiredArcaneResistance`(필요 마도저항)·`ArcanePressure`(마도 압력), `AbyssDungeonGroup.Season`(시즌), `AbyssDungeonDifficulty.HellStep`·`DisplayName`(지옥 단계·이름)
  - 기준값이 있는 **가장 최근 어비스 시즌**(현재 `Abyss_Season_03` = 룬다)의 지옥 난이도만 지옥 단계 순으로 비교한다. 같은 시즌 던전끼리 값이 다르면 검증 실패로 보고 마지막 정상 데이터를 유지한다.
  - 게임 데이터에 시즌 이름이 없어 알려진 시즌만 이름을 붙인다(3 = `룬다 어비스`, 그 밖은 `어비스 시즌 N`).
  - 새 지옥 난이도에 기준값이 생기면 코드 수정 없이 결과에 추가된다. 클라이언트 데이터에 미리 들어온 난이도는 개방 전에도 보일 수 있다.
- 데이터가 하나도 없으면(캐시 없음 + 저장소 접근 실패) `UnpackDataMessages.NoData("마도저항")`으로 응답한다.

## 계산식 (커뮤니티 추정식)

R = 입력 마도저항, P = 마도 압력, Δ = R − P

- 주는 피해 배율: Δ < 0이면 `2^(Δ/1000)`, Δ ≥ 0이면 `1 + 0.5 × (1 − 2^(−Δ/4000))`
- 받는 피해 배율: Δ < 0이면 `1 + ((P − R)/1000)^0.75`, Δ ≥ 0이면 `1`
- 증감률 = (배율 − 1) × 100. 중간값은 반올림하지 않고 표시할 때만 소수점 한 자리로 반올림한다.
- 받는 피해를 주는 피해 배율의 역수로 계산하지 않는다.

### 근거와 한계

- [공식 마도 저항 / 마도 압력 가이드](https://mabinogimobile.nexon.com/Info/Guide/3481543): 미달 시 주는 피해 감소·받는 피해 증가, 초과 시 최종 피해량 증가(최대 50%)를 설명하지만 수식은 공개하지 않는다.
- [8/13 업데이트](https://mabinogimobile.nexon.com/News/Update/3521707): 상한 40%→50%, 초과 예시 500→4.1%, 1,000→7.9%, 2,000→14.6%, 4,000→25%, 8,000→37.5%.
  - 추정식은 4,000·8,000에서 정확히 25%·37.5%, 500·2,000에서 4.1%·14.6%로 일치한다.
  - 1,000에서는 추정식이 7.955…%라 소수 첫째 자리 반올림 시 **8.0%**로, 공식 예시 7.9%와 0.1%p 다르다(공식 표가 버림 표기로 보임). 몰리는 요청 규칙대로 반올림한다.
- [커뮤니티 계산기](https://erinndata.pages.dev/calc/): 주는 피해 식과 같다. 받는 피해 식은 없다.
- [나무위키 능력치 문서](https://dark.namu.moe/w/%EB%A7%88%EB%B9%84%EB%85%B8%EA%B8%B0%20%EB%AA%A8%EB%B0%94%EC%9D%BC/%EB%8A%A5%EB%A0%A5%EC%B9%98): 받는 피해 식 `1+((압력−저항)/1000)^0.75`을 싣고 출처로 [디시인사이드 글](https://gall.dcinside.com/mgallery/board/view/?id=enban&no=1259760)을 든다. 그 글은 주는 피해 초과 식만 있고 실험 방법·측정 데이터가 없어 **받는 피해 식의 원 실험 자료는 확인하지 못했다.**

## 출력

임베드 하나. 제목 `마도저항 확인 · 7,200`(천 단위 쉼표), 설명 `룬다 어비스 난이도별 마도 압력과 비교한 결과예요.`(어비스 이름은 게임 데이터 시즌 기준), 지옥 단계 순서의 필드(현재 지옥1→지옥4).

```
지옥1
주는 피해 +19.2% · 받는 피해 0%
지옥2
주는 피해 +4.9% · 받는 피해 0%
지옥3
주는 피해 −34.0% · 받는 피해 +68.2%
지옥4 ⚠️ 입장 기준 미달
주는 피해 −71.3% · 받는 피해 +155.4%
```

- 증가는 `+`, 감소는 `−`(U+2212). 반올림 결과가 0이면 `0%`(음수 0 없음).
- 입력이 필요 마도저항보다 **낮을 때만** `⚠️ 입장 기준 미달`. 같으면 미달 아님. `입장 불가`라고 단정하지 않는다.
- 꼬리말: `커뮤니티 추정식 기준 · 마도저항 효과만 계산하며 다른 장비 효과·버프는 제외합니다.` 미달 항목이 있으면 파티장이 조건을 충족하면 함께 입장할 수 있다는 안내를 덧붙인다.

## 사용하는 기존 데이터 / 새로 필요한 데이터

- 게임 데이터 저장소의 마도저항 데이터(`UnpackMagicResistanceDataset`, `/해연비용계산`과 공유). 계산식만 코드에 둔다.

## API 사용량

외부 API 호출 없음. 게임 데이터 저장소는 봇 전체에서 1시간마다 커밋 확인 1회를 다른 데이터와 함께 쓰고, 명령 실행은 저장소를 호출하지 않는다. 길드·사용자 증가 영향 없음.

## 최소 구현 범위

최근 어비스 시즌(현재 룬다)의 지옥 난이도 비교. 기준값은 게임 데이터 저장소에서 읽는다.

## 제외 범위

장비 추천, 감정 횟수, 제작·구매 비용 계산, 캐릭터 조회, 다른 콘텐츠(레이드·나이트메어 드릴 등)의 마도 압력.

## 성공 기준

- 명령 주간 사용 횟수와 재사용률
- 기준값 변경 공지 후 반영까지의 시간
