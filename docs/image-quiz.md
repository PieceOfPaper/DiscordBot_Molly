# 이미지퀴즈 기획서

> 문서 상태: 구현  
> 최종 갱신: 2026-11-01  
> 구현: `Commands/ImageQuizCommand.cs`, `Quiz/QuizQuestions.cs`, `SkillQuiz/`, `World/`(NPC·지역 데이터, NPC 이미지 캐시), `Commons/ClassIcons.cs`(CombatJob 매핑)

## 기능명

`/이미지퀴즈`: 클래스·NPC·스킬 아이콘을 보고 이름을 맞히는 선착순 퀴즈.

## 분류

놀이.

## 해결하려는 문제

`/자음퀴즈`는 글자 힌트로 이름을 떠올리는 놀이다. 게임을 오래 한 사람은 이름보다 얼굴·아이콘을 먼저 기억하므로, 그림을 보고 바로 맞히는 쪽이 더 빠르고 반응이 크다.

## Discord에서 제공하는 이점

게임 안에서는 할 수 없는, 여러 사람이 같은 그림을 보고 선착순으로 맞히는 짧은 대화 소재를 명령 한 번으로 만든다.

## 핵심 사용자 흐름

1. `/이미지퀴즈 문제종목:NPC`(문제수·제한시간은 자음퀴즈와 같은 기본값 10개·30초)
2. 실행 채널에 게임 스레드가 생기고 30초 뒤 시작한다.
3. 문제마다 그림, 종류, 힌트(NPC는 배치된 지역, 클래스는 없음)가 나온다. 스킬아이콘으로클래스는 15초 후 스킬 이름을 같은 Embed에 표시한다(제한시간 15초 이하는 생략).

## 스킬 아이콘으로 클래스

- 공개 전직 클래스의 `SkillSlot` Slot01~06(액티브)·PassiveSlot01~06(패시브) 연결만 사용하고 일반 시즌 행과 룬 모딩 행을 모두 검사한다. `SeasonSkillSlot`은 별도 시즌 전용이므로 쓰지 않는다.
- 전투숙련, 기본 공격·팔라딘 변신, 이름·그림 없는 항목, 클래스 간 공유 그림은 제외한다. 같은 클래스의 같은 그림은 기본 스킬 우선 대표 하나로 합친다.
- `Skill` 아이콘이 `.asset`이면 대응 `.asset.json`의 `CommonIconAsset` 리소스에서 128px PNG를 우선 선택하고, 없으면 정의된 PNG 중 마지막(최대 크기)을 쓴다. ID로 파일명을 추측하지 않는다.
- `MOLLY_DATA_DIR/unpack/skill-icons`에 콘텐츠 SHA 이름으로 보관한다. 명령·출제 시 GitHub 요청은 없고, 새 커밋 때 필요한 이미지뿐 받는다. 클래스 순서를 매 순회 섞고 클래스별 남은 이미지 하나씩을 골라 출제 기회를 균등하게 한다.
4. 스레드에 이름을 채팅하면 가장 먼저 맞힌 한 명이 1점을 얻는다.
5. 끝나면 우승자를 알리고 스레드를 보관한다.

## 사용하는 기존 데이터

- 진행: `SpeedQuizService`(자음퀴즈·스피드퀴즈와 같은 출제·판정·종료, 서버당 퀴즈 하나), `/놀이종료`.
- 클래스: 게임 데이터 클래스 목록(`UnpackClassDataset`, 공개된 전직 클래스 21개)과 배포 에셋 `assets/class_icons`. 게임 데이터의 클래스 아이콘은 흰색 실루엣뿐이라 쓰지 않는다. `ClassIcons.FromCombatJob`이 CombatJob.Id를 아이콘 ID로 연결한다(배틀 코드·시트는 건드리지 않음).

## 새로 필요한 데이터

- **NPC·지역**(`World/UnpackWorldDataset`): 자음퀴즈의 Google Sheets `NPC`·`지역` 탭을 대신한다.
  - 지역: 지도 빠른 이동이 있는 채널의 GameSpace 중 마을(`Field`)·사냥터(`BattleField`). 2026-11-01 기준 14곳(시트 `지역` 탭과 같음).
  - NPC: 그 지역 월드의 NPC 배치 파일에 있고 칭호가 있는 NPC. 같은 이름은 합친다. 2026-11-01 기준 95명.
  - 제외되는 것: 게시판·보관함·이름 없는 엑스트라(칭호 `-`), 이벤트·퀘스트로만 나오는 NPC(상설 배치 없음), 개발 중 지역(빠른 이동 없음)의 NPC.
- **NPC 이미지**(`World/NpcPortraitCache`): `NPC.ProfileImage` PNG(128×128 원형 초상). 기본 실루엣·여러 NPC가 나눠 쓰는 그림은 출제하지 않는다.

## API 사용량

외부 API는 쓰지 않고 게임 데이터 저장소(GitHub REST, 인증 요청 시간당 5,000회 한도)만 쓴다.

| 항목 | 요청 |
| --- | --- |
| 변경 확인 | 1시간마다 `version.json` 커밋 1회(모든 게임 데이터 공용, 늘지 않음) |
| NPC·지역 다시 만들기 | 버전 1 + 시트 4 + 배치 파일 14 = 19회(약 1.7MB), 버전이 바뀌었을 때와 봇 시작 때만 |
| NPC 이미지 | 이미지 폴더 트리 1회 + blob SHA가 바뀐 파일 수(처음 95개, 약 1MB) |
| 명령 실행 | 0회(받아 둔 데이터·이미지만 읽음) |

- 길드·사용자 수와 무관하다.
- 캐시: `MOLLY_DATA_DIR/unpack/world.json`, `MOLLY_DATA_DIR/unpack/npc-portraits/<blob SHA>.png` + `manifest.json`. 재시작 후 요청 없이 바로 쓴다.
- 실패: 마지막 정상 데이터·받아 둔 이미지를 유지하고 10분 뒤 다시 시도한다. 일부 이미지만 받았으면 받은 것만 출제한다. 데이터가 하나도 없으면 `UnpackDataMessages.NoData`로 그 종목만 막는다.
- 저장소 갱신 스크립트가 `version.json`을 덤프의 마지막 커밋에 올려야 시트·월드 데이터·이미지가 같은 버전으로 맞는다.

## 최소 구현 범위

- `/이미지퀴즈` 종목 `클래스`·`NPC`, 옵션 `문제수`·`제한시간`.
- `/자음퀴즈`의 NPC·지역 종목을 같은 게임 데이터로 교체(시트 `NPC`·`지역` 탭은 더 이상 읽지 않음).

## 제외 범위

- 클래스와 NPC를 섞는 종목.
- 이미지 일부만 보여주기·흐리게 하기 같은 난이도 조절(이미지 처리 라이브러리가 필요).
- 라이트 테마에서 흰색 클래스 아이콘이 잘 안 보이는 문제(기존 `ClassIcons`와 같은 전제).
- 이벤트·퀘스트 NPC, 몬스터, 아이템 그림.

## 성공 기준

- 이미지퀴즈 한 판의 완료율(`/놀이종료` 없이 끝까지 진행된 비율)이 자음퀴즈와 비슷하거나 높다.
- 주간 실행 횟수가 자음퀴즈 NPC·클래스 종목과 비슷하거나 높다.
- NPC 이미지 누락으로 출제 가능한 문제가 줄어든 경우를 로그(`[게임데이터:NPC 이미지] 확인 완료 … 저장소에 없음 n`)로 확인할 수 있다.
