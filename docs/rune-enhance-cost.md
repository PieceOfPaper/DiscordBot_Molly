## 2. 명령

```
/룬강화비용 부위:무기 현재강화:10 목표강화:15
/룬강화비용 부위:무기 현재강화:10 목표강화:15 강화포인트:60
```

| 옵션 | 필수 | 설명 |
| --- | --- | --- |
| `부위` | 필수 | 무기·방어구·엠블럼·장신구 |
| `현재강화` | 필수 | 0~20(게임 데이터 최대 단계로 다시 검사) |
| `목표강화` | 필수 | 0~20, 현재 이상 |
| `강화포인트` | 선택 | 현재 단계에서 다음 단계까지 진행률(%). 0~100, 소수 첫째 자리까지(게임 표시 정밀도). 비우면 0% |

입력 검증(보정하지 않고 안내):

- 범위 밖 단계, 목표 < 현재, 강화포인트 0 미만·100 초과·소수 둘째 자리 이상은 오류 안내.
- 현재 = 목표면 추가 비용 0 안내. +20(최대)은 강화 포인트가 없으므로 강화포인트 입력 시 오류.
- 강화포인트 100%는 확정 강화 대기 상태로 계산한다.
- 진행률은 게임이 둘째 자리 이하를 버려 표시하므로, 그 표시가 나오는 가장 작은 포인트(`ceil(폭 × 진행률)`)로 바꾼다.

## 3. 데이터 연동

- `Rune`: `Season02`, `Rarity` 전설·신화, `Tier` 10 룬의 `RuneAttachableType`·`EnhanceCostGroupId`·`CarvingRuneEnhanceMaxLevel`. 전설+·전설++는 같은 희귀도의 다른 룬이라 함께 포함된다(공식 안내: 같은 시즌 전설과 규칙·확률 동일).
- 비용표는 `Rune.Tier`(10)와 이름 숫자(`RuneEnhance_Tier11_*`)가 다르므로 이름이 아니라 `EnhanceCostGroupId`로만 연결한다. 부위마다 비용표·최대 단계가 하나여야 하며 다르면 검증 실패(마지막 정상본 유지).
- 2026-11-01 데이터: 무기 `Tier11_Wea`(17개), 방어구 `Tier11`(62개), 엠블럼 `Tier11_Emb`(10개), 장신구 `Tier11_Acc`(189개). 네 부위는 누적 포인트·확률이 같고 1회 비용만 다르다(엠블럼 = 장신구).
- `RuneEnhanceCost`: `EnhanceStep`은 **목표 단계**다(+10 → +11은 11행). `EnhancementPoint`는 **누적** 기준값이고 단계 폭은 이웃 행의 차이다. `Cost.Gold`·`Cost.Ingredients[0].Amount`·`Cost.CatalystCount`를 1회 비용으로 쓴다. `ReturnAmount`는 실패 반환량이 아니다(실측: 실패해도 파편 전량 소모).
- `Consumable.DisplayName`: 룬의 파편(`RunePowder_Season1`)·강화 재연소 촉매(`RuneEnhanceCatalyst`) 이름.
- 캐시는 `MOLLY_DATA_DIR/unpack/rune-enhance.json`. 데이터가 하나도 없으면 `UnpackDataMessages.NoData`로 안내한다.

## 4. 강화 포인트 규칙과 근거

| 규칙 | 근거 |
| --- | --- |
| 단계 L ⇔ 누적 포인트 ∈ [EP(L), EP(L+1)), 진행률 = (포인트 − EP(L)) ÷ 폭 | 커뮤니티의 '★ 승급 시 단계 하락 경계'(15강 3%, 17강 8%, 18강 63%, 19강 65%)가 현재 데이터의 누적값으로 정확히 재현됨, 공식 가이드 '누적 포인트 이전' |
| 성공: 그 단계 0% → 100% 전체 포인트(폭)를 받고 100% 초과분은 다음 단계로 이관 | NEXON NOW 확률 안내, 실측 2건 |
| 실패: `round(폭 × 성공률 ÷ 2)` 포인트 | NEXON NOW '실패 시 강화 단계별 강화 포인트(%) 증가량' 표 532칸(★0~★6 이상 × 4부위 × +4~+19)과 이 식이 모두 일치(버림·실수값은 각각 68·72칸 불일치). 실측 +1.5% 2회 |
| 실패로 100% 이상: 재료·골드 소모 없이 100% 확률 강화, 초과분 이관 | NEXON NOW 확률 안내, 클라이언트 UI(`CarvingEnhancementUI`: 포인트가 차면 재료·골드 칸을 숨기고 재료 부족이어도 버튼 활성) |
| 확정 강화는 성공 포인트를 다시 더하지 않고 초과분만 이관 | 공식 문구 '초과분은 다음 단계로 이관'의 해석(측정 안 함) |
| 촉매: 한 번 분량 재료로 두 번 독립 판정, 두 판정의 성공·실패 포인트를 모두 받음. 한 번이라도 성공하면 강화 성공 | NEXON NOW 확률 안내(조합 확률 p², p(1−p), (1−p)²), 공식 가이드, 실측(두 번 실패 +3.0%, 1차 성공·2차 실패 시 실패 포인트 추가) |
| 촉매는 `CatalystCount > 0`인 단계(현재 +10 → +11부터)에서만, 100% 상태에서는 사용 불가 | 데이터, NEXON NOW 확률 안내 |
| 실패하면 장비가 저주받고 저주 상태에서는 강화 불가 | 게임 문자열·공식 가이드(저주 해제 비용은 계산 제외) |

## 5. 계산 방식

- 상태는 (단계 L, 그 단계 안 포인트 x)이고 기댓값 점화식을 목표 단계부터 거꾸로 푼다. 평균 포인트로 근사하지 않고 정수 포인트 상태 전체를 계산한다.
  - 촉매 미사용: 성공 p → (L+1, x), 실패 → (L, x + 실패 포인트)
  - 촉매 사용: 성공·성공 p² → (L+1, x + 폭), 성공·실패 / 실패·성공 2p(1−p) → (L+1, x + 실패 포인트), 실패·실패 (1−p)² → (L, x + 실패 포인트 × 2)
  - x ≥ 폭이면 비용 없이 (L+1, x − 폭)(확정 강화, 두 번 성공 등으로 연쇄 가능)
- 골드·파편·촉매를 각각 따로 푼다(자원별 상태 배열 하나, 최대 약 12MB). +0 → +20 전 구간이 약 0.35초, 일반 구간은 수 ms라 명령은 응답을 먼저 미룬 뒤 계산한다.
- 촉매 사용 결과는 '사용 가능 구간에서 매번 사용' 기준이고, 사용할 수 없는 구간은 일반 강화로 계산한다.
- 표시: 골드 정수 반올림, 재료·촉매 소수 첫째 자리 반올림. 총합과 차이는 반올림 전 내부값으로 계산한 뒤 반올림한다.
- 계산 엔진(`RuneEnhance/`)과 Discord 표시(`Commands/RuneEnhanceCostCommand.cs`)는 분리되어 있다.

## 7. 남은 제한

- 촉매로 성공했을 때 이월 포인트의 0.1~0.3%p 차이(4절)는 원인을 모른다.
- 확정 강화(100% 이상) 시 성공 포인트를 더하지 않는다는 해석은 측정하지 않았다.
- 시즌 2 ★10 전설·신화만 지원한다. 다른 시즌·등급은 같은 규칙이 공식 안내에 있으나 범위 밖이다.
- 공식 규칙이나 데이터가 바뀌면(예: 실패 포인트 표 변경) `RuneEnhanceRules`와 이 문서를 함께 고친다. 데이터 변경은 공용 보관소가 자동 반영한다.
