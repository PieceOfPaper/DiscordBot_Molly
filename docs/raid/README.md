# 몰리 레이드 기획서

> 문서 상태: 기획 초안 · 구현 보류  
> 최종 갱신: 2026-10-04  
> 이 문서는 개발 참고용이다. 사용자의 별도 구현 승인 전에는 명령 등록, 전투 코드, DB, Google Sheets를 수정하거나 레이드 기능을 개발하지 않는다.  
> 관련 문서: [콘텐츠 기획 가이드라인](../content-planning-guidelines.md), [배틀 기획서](../battle/README.md), [마물 퇴치 증표 기획서](../currency/monster-hunt-token.md)

## 1. 개요와 목적

분류는 **놀이 기능**이다. 기존 배틀 캐릭터들이 4~8인 규모의 파티를 구성하고 특정 몬스터와 완전 자동으로 전투하는 Discord 레이드다.

첫 대상은 글라스기브넨이다. 인게임 레이드의 상징성과 익숙한 소재를 활용하되, 실제 게임을 조작하거나 실제 게임 보상을 지급하지 않는다.

사람들이 Discord에서 대화하다가 버튼 한 번으로 함께 참여하고 전투 결과를 구경하는 놀이를 제공한다. 인원을 오래 모으거나 전투 중 계속 화면을 확인할 필요가 없도록 30초 모집과 허수아비 충원을 사용한다. 별도 캐릭터 성장이나 일일 과제를 추가하지 않는다.

## 2. 승인 범위와 결정 상태

이 문서에 기획 규칙이 확정되어 있다는 사실은 구현 승인을 뜻하지 않는다. 기획을 더 다듬은 뒤 별도 승인으로 구현을 시작한다.

### 2.1 확정된 기획

| 항목 | 규칙 |
| --- | --- |
| 명령어 | `/레이드` |
| 레이드 선택 | 명령 파라미터로 갈 레이드를 선택 |
| 현재 대상 | `글라스기브넨` |
| 생성 | 유저가 기존 배틀처럼 직접 생성 |
| 모집 | 생성된 스레드에서 30초 동안 참여 버튼으로 모집 |
| 전투 조작 | 참가 이후 완전 자동. 공격·방어·패턴 대응 버튼 없음 |
| 캐릭터 | 기존 배틀 캐릭터 사용 |
| 파티 규모 | 레이드 정원 4~8인. 레이드별 구체적인 정원은 별도 확정 |
| 부족 인원 | 모집 종료 시 정원까지 허수아비로 충원 |
| 허수아비 클래스 | 전투에 사용 가능한 클래스 중 무작위 선정 |
| 허수아비 이름 | `허수아비 1`부터 순서대로 부여 |
| 허수아비 전투력 | 실제 참가자의 평균 전투력 |
| 승리 | 보스 HP가 0이 되면 승리 |
| 패배 | 파티 전멸 시 종료 |
| 보스 브레이크 | 기존 배틀보다 훨씬 많은 칸 사용. 수치는 밸런싱으로 결정 |
| 부활 | 사망 후 대략 1턴 뒤 자동 부활. 정확한 턴 경계는 미정 |
| 부활 제한 | 레이드 종류·난이도별 부활 횟수 설정 |
| 보상 재화 | 마물 퇴치 증표 |
| 보스 패턴 | 사용자가 추후 별도로 제공 |

### 2.2 미정과 제안의 취급

이전 논의에서 제안한 파티 공유 부활 횟수, 부활 대기자보다 전멸 판정을 우선하는 방식, 전원 동일 보상 등은 **아직 확정하지 않았다**. 구현자가 이 문서를 읽고 임의의 기본값으로 확정해서는 안 된다.

## 3. 명령과 사용자 흐름

예시:

```text
/레이드 레이드:글라스기브넨
```

명령 이름과 레이드 선택 방식은 확정이다. 예시의 옵션 이름 `레이드`, 필수 여부, 기본값과 선택 UI는 구현 전 확정한다. 현재 선택 후보는 글라스기브넨 하나이며, 명령 자체는 아직 제공하지 않는다. 난이도 옵션을 추가할지도 미정이다.

1. 사용자가 레이드를 선택해 명령을 실행한다.
2. 몰리가 모집·전투용 스레드를 생성하고 참여 버튼과 모집 마감 시각을 표시한다.
3. 참여하고 싶은 사용자가 30초 이내에 참여 버튼을 누른다.
4. 모집 마감 후 실제 참가자와 평균 전투력을 확정하고 부족한 자리를 허수아비로 채운다.
5. 기존 배틀 시스템을 기반으로 파티와 보스의 전투를 자동 진행한다.
6. 보스 처치 또는 파티 전멸로 종료한다.
7. 결과와 확정될 보상 규칙에 따른 지급 내용을 표시한다.

생성자의 자동 참가 여부, 실제 참가자 최소 인원, 실제 참가자 0명일 때의 취소 처리, 정원 도달 시 조기 출발 여부는 미정이다. 모집 중 탈퇴, 정원 초과 요청, 마감과 참여 요청이 겹치는 경우도 구현 전에 정한다.

## 4. 허수아비 충원

정원이 8명인 레이드에 실제 유저 3명이 참여하면 허수아비 5명을 추가한다.

```text
실제 참가자 전투력: 30,000 / 36,000 / 42,000
평균 전투력: 36,000
허수아비 1~5의 전투력: 각각 36,000
```

- 평균 계산에는 실제 참가자만 포함한다.
- 기존 허수아비를 평균 계산에 다시 포함하지 않는다.
- 사용 가능한 클래스는 원본 클래스 목록 전체와 동일하다고 가정하지 않는다. 배틀 데이터와 동작이 준비된 클래스를 기준으로 후보를 정의해야 한다.
- 클래스 중복 허용 여부, 클래스별 추첨 확률, 탱커·힐러 등 역할 보장 여부는 미정이다.
- 평균 소수점 처리와 전투력에서 능력치·스킬을 구성하는 방식은 기존 배틀의 생성 규칙을 확인한 뒤 정한다.
- 허수아비가 실제 유저의 장비나 개별 능력치를 그대로 복제한다는 규칙은 없다.
- 실제 참가자의 정보 갱신·조회가 실패했을 때 허수아비로 대체할지는 미정이다.
- 실제 유저가 적더라도 정원만큼 전투원이 구성되므로, 보스는 완성된 파티 정원을 기준으로 밸런싱을 검토한다.

글라스기브넨이 반드시 8인으로 확정된 것은 아니다. 8인 예시는 충원 규칙을 설명하기 위한 예시다.

## 5. 자동전투와 파티 전투

캐릭터, 클래스, 스킬, 패시브, 자원, 효과와 행동 AI는 기존 배틀 시스템을 기반으로 한다. 재사용 가능 여부와 다대다 전투 확장 범위는 구현 승인 후 코드와 최신 시트를 확인하여 결정한다.

전투 중 유저 입력을 요구하지 않는다. 보스 패턴 대응과 아군 지원도 시스템이 자동으로 판단해야 한다.

구현 전 결정할 공통 규칙:

| 영역 | 결정할 내용 |
| --- | --- |
| 턴 | 개인 행동과 전체 라운드 중 무엇을 1턴으로 볼지 |
| 행동 순서 | 파티원·보스·수하의 행동 순서와 행동 횟수 |
| 공격 대상 | 보스·수하가 함께 있을 때 대상 선정 |
| 아군 지원 | 회복·보호·강화 대상과 사망자 취급 |
| 중첩 효과 | 여러 파티원의 같은 강화·약화 중첩 규칙 |
| 보스 상태 이상 | 기절·빙결·도발 등 적용 여부와 제한 |
| 브레이크 | 칸 수, 누적·회복·리셋, 부활·페이즈와의 관계 |
| 종료 순서 | 지속 피해 등으로 보스 처치와 전멸이 동시에 발생할 때 |
| 무한 전투 방지 | 최대 턴·시간 제한과 초과 결과 |
| 배틀 기능 분리 | 기존 1대1 전적·승부 예측·돌발 이벤트 적용 여부 |

기존 배틀의 최대 행동 초과 시 HP 비율 판정을 레이드에 자동으로 가져오지 않는다. 레이드의 승리 조건은 보스 처치이며, 제한 초과의 결과는 별도로 정해야 한다.

## 6. 사망과 부활

사망 후 약 1턴 뒤 자동으로 부활할 수 있으며, 부활 횟수는 레이드·난이도별로 제한한다. 숫자는 아직 정하지 않는다.

| 미정 항목 | 확인해야 할 내용 |
| --- | --- |
| 횟수 소유 | 파티 전체 공유 또는 개인별 |
| 횟수 차감 | 사망 시 예약 또는 실제 부활 시 차감 |
| 허수아비 | 부활 가능 여부와 횟수 소비 방식 |
| 부활 시점 | 1턴의 정확한 기준과 첫 행동 가능 시점 |
| 전멸과 부활 | 전원 사망했으나 부활 대기자가 있을 때 즉시 패배 여부 |
| 동시 사망 | 남은 횟수가 부족할 때 부활 대상 선정 |
| 회복 상태 | 부활 HP, 자원, 스킬 대기 시간, 강화·약화 유지 여부 |
| 부활 소진 | 횟수가 없을 때 남은 생존자만 계속 싸우는 판정 |

위 항목이 확정되기 전에는 특정 부활 순서를 코드나 시트에 반영하지 않는다.

## 7. 보스와 난이도

첫 보스 후보는 글라스기브넨이다. 보스 패턴은 사용자가 후속 기획으로 제공하며, 기존 논의의 패턴 예시는 확정 목록으로 취급하지 않는다.

원본 참고:
- [글라스기브넨 레이드 자료](https://namu.wiki/w/마비노기%20모바일/레이드/글라스기브넨)

다음 자료가 필요하다:

- 보스 능력치, 정원, 난이도 목록
- 기본 공격과 패턴의 효과·대상·발동 조건·우선순위
- 페이즈 전환과 수하 소환 여부
- 브레이크 가능 시점과 칸 수
- 난이도별 부활 횟수와 보상
- 몰리봇의 자동전투에서 처리할 각색 규칙

참고 자료의 실제 게임 수치를 몰리 배틀 수치로 그대로 사용하지 않는다. 브레이크 칸 수를 비롯한 전투 수치는 모의 전투로 조정하며, 목표 전투 길이와 성공률은 별도 확정한다.

## 8. 마물 퇴치 증표 보상

레이드 보상으로 마물 퇴치 증표를 사용하는 방향은 확정이다. 출석 외의 추가 수급처로 계획하되 현재 지급 기능은 구현하지 않는다.

기존 증표 정책을 따른다:

- 실제 게임 재화와 연동하지 않는 몰리 전용 놀이 재화다.
- 레이드가 진행된 Discord 서버의 사용자 잔액에 반영한다.
- 몰리가 이름을 말할 때는 `마물 퇴치 증표` 풀네임을 사용한다.
- 이름을 생략한 수량 표기는 전용 이모지를 앞에 붙여 `(증표 이모지)10개`로 표시한다.
- 공개 메시지에는 보유 잔액을 표시하지 않는다. 지급량과 잔액은 구분한다.
- 기존 공용 증표 저장소와 원장을 활용하고 중복 지급을 방지해야 한다.
- 숫자는 기존 `증표규칙` 시트에서 관리하는 방향을 따른다. 신규 ID와 구조는 별도 확정하며 지금 시트를 수정하지 않는다.

다음은 미정이다: 입장 비용, 승리·실패별 지급 여부와 지급량, 반복 보상 제한, 초기화 기준, 사망자·중도 이탈자의 수령 조건, 기여도별 차등 여부, 허수아비의 보상 처리. 허수아비 보상 제외와 실제 참가자 동일 보상은 검토 제안이며 아직 확정 규칙이 아니다.

## 9. 데이터와 운영 비용

### 기존 자산

- 기존 배틀 캐릭터 등록·조회 정보와 전투 스냅샷
- 클래스·스킬·패시브 원본 및 배틀 계산용 시트
- 배틀의 능력치 계산, 자동 행동, 효과·자원·전투 이벤트
- 스레드·버튼·게임 진행 상태 관리
- 서버별 마물 퇴치 증표 잔액·원장과 `증표규칙` 시트

원본 스킬 설명만으로 자동전투가 가능하다고 가정하지 않는다. 최신 배틀용 데이터와 구현이 준비된 클래스만 사용하는 기준이 필요하다.

### 새 데이터 후보

레이드 정의, 보스·수하 능력치, 난이도, 정원, 패턴과 페이즈, 브레이크, 부활, 보상 규칙이 필요하다. 시트 이름·헤더·ID·DB 구조는 아직 설계 확정 전이며 신규 테이블을 생성하지 않는다.

### 외부 호출과 캐시

- 전투 턴마다 외부 API를 조회하는 구조는 계획하지 않는다.
- 전투 데이터는 시작 시 고정한 정상 스냅샷을 사용하도록 검토한다.
- 실제 참가자 캐릭터 갱신에는 기존 배틀의 조회·캐시 정책을 재사용하는 방향이다. 배틀 문서는 1시간 유효 시간을 정의한다.
- 8인이라면 만료된 실제 참가자 정보가 최대 8명일 수 있으나, 캐릭터 조회 1건이 HTTP 요청 1회라는 뜻은 아니다. 실제 호출 수는 구현 조사 후 산정한다.
- 일일 호출량은 레이드 횟수와 캐시가 만료된 참가자 조회 요청량에 따라 계산해야 하며 현재 숫자를 확정하지 않는다.
- 허수아비의 정보를 얻기 위한 별도 외부 캐릭터 검색은 필요하지 않은 방향이다.
- 클래스·보스 데이터는 공용 캐시를 활용한다. 신규 레이드 데이터의 갱신 주기와 장애 시 처리, 최초 정상 데이터가 없을 때의 동작은 미정이다.

## 10. 표시와 예외 처리

표시할 정보 후보는 모집 중 레이드 이름·참가자·정원·마감 시각, 전투 중 보스 HP·파티 생존 상태·부활 횟수·중요 사건, 종료 시 성공·실패와 보상이다. 정확한 메시지 형식·중계 간격·결과 스레드 보관 방식은 미정이다.

구현 전에 확인할 예외:

- 미등록 캐릭터, 사용 불가능한 클래스, 조회 실패
- 중복 클릭·동시 참가·모집 마감 경합
- 스레드 생성 실패 또는 삭제
- 배틀·다른 놀이·다른 레이드와 동시 진행 제한
- 참가 후 이탈·강제 종료
- 봇 재시작 시 모집·전투·보상의 복구 또는 무효 처리
- 재시도 시 보상 중복 지급

기존 배틀은 길드 단위 게임 잠금과 전투 종료 후 스레드 보관 규칙을 가진다. 레이드가 이를 동일하게 사용할지는 미정이다. 예외 정책을 정하기 전 배틀의 동작을 자동으로 확정 규칙으로 복사하지 않는다.

## 11. 첫 구현 후보 범위와 성공 기준

다음은 **향후 구현 범위를 정하기 위한 후보**이며 개발 착수 지시가 아니다.

- 글라스기브넨 1종
- 레이드 선택 명령·30초 버튼 모집·허수아비 충원
- 기존 캐릭터의 완전 자동 파티 전투
- 후속 확정 패턴과 브레이크·부활
- 결과 중계와 확정된 증표 지급 규칙

초기 제외 범위는 수동 조작, 별도 성장·장비·상점, 랜덤 레이드 출현, 레이드 승부 예측, 다른 보스 확대다. 난이도 수와 첫 버전 패턴 수는 미정이다.

성공 기준 후보:

- 명령과 참여 버튼만으로 전투 결과까지 진행된다.
- 모집 종료 후 부족한 인원 때문에 장시간 대기하지 않는다.
- 참가자가 전투 중 추가 조작을 하지 않아도 된다.
- 전투 길이·완료율·성공률을 확인해 반복 관전하기에 부담 없는 밸런스로 조정한다.
- 재화 중복 지급·서버 간 잔액 혼합 없이 종료된다.
- 기존 배틀 동작을 변경하지 않고 파티 전투 확장을 검증한다.
