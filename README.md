# DiscordBot_Molly
마비노기 모바일용 디스코드 봇 **Molly**.  
이벤트/랭킹 크롤링, 간단 유틸 커맨드를 제공합니다.

## 핵심 기능
- 진행 중 이벤트 조회(마감일/상시 구분)
- 이벤트 마감 알림 등록(지정 시간 전)
- 전투력/매력/생활력/종합 랭킹 조회
- 간단 유틸(핑/시간/이미지/개발자)

## 빠른 시작
1. 패키지 복원
```bash
dotnet restore
```

2. Playwright(Chromium) 설치

아래 명령은 PowerShell 7(`pwsh`)이 필요합니다. `dotnet restore`나 `dotnet build`만으로는 브라우저가 설치되지 않습니다.
```bash
dotnet build
pwsh bin/Debug/net10.0/playwright.ps1 install chromium
```

Apple Silicon Mac에서 `pwsh`가 없다면, 위 `dotnet build` 후 빌드에 포함된 도구로 설치할 수 있습니다(프로젝트 루트에서 실행):
```bash
bin/Debug/net10.0/.playwright/node/darwin-arm64/node bin/Debug/net10.0/.playwright/package/cli.js install chromium
```

다운로드가 오류 없이 완료된 뒤 다음 단계로 진행하세요. `Executable doesn't exist ... chromium_headless_shell-...` 오류는 필요한 브라우저가 없다는 뜻입니다. Playwright 패키지 버전을 변경했다면 다시 빌드하고 설치 명령도 다시 실행하세요. 설치는 봇을 실행할 동일한 OS 사용자 계정에서 수행해야 합니다.

3. Discord 토큰 등록
```bash
dotnet user-secrets set "Discord:Token" "YOUR_TOKEN"
```

4. (선택) 테스트 길드 ID 등록
```powershell
# Windows PowerShell
setx Discord__GuildId "TEST_GUILD_ID"
```
```bash
# macOS/Linux
export Discord__GuildId="TEST_GUILD_ID"
```

5. 실행
```bash
dotnet run
```

## 설정
- `Discord:Token`  
  `user-secrets`로 설정합니다.
- `Discord:GuildId`  
  테스트 길드 ID(선택). 설정 시 길드에만 슬래시 명령을 등록(즉시 반영).  
  비어 있거나 0이면 글로벌 등록(전파 지연 가능).  
  환경변수로는 `Discord__GuildId` 사용.
- `MOLLY_DATA_DIR`  
  영구 데이터 저장 위치입니다. 이벤트 마감 알림 SQLite DB와 룬·쪽지 캐시가 이 경로 아래에 저장됩니다. 개발 시에는 프로젝트별로 `MOLLY_DATA_DIR="$PWD/.molly-data"`를 권장하며, `.molly-data/`는 Git에 포함하지 않습니다.
- `MollyDatabase__Path`<br>
  선택 설정입니다. 지정하면 SQLite DB의 경로를 직접 바꿉니다. 미지정 시 `MOLLY_DATA_DIR/database/molly.sqlite`를 사용합니다.
- `GoogleSheets:SpreadsheetId`<br>
  전투를 포함한 Google Sheets 문서 ID입니다. `/배틀`은 `클래스`, `스킬`, `배틀스킬`, `배틀스킬효과`, `배틀스킬파생`, `배틀자원`, `배틀규칙`, `배틀돌발이벤트`, `배틀돌발이벤트효과` 탭을 시작 시 한 묶음으로 읽습니다. 하나라도 검증에 실패하면 마지막 정상 스냅샷만 사용하며, 정상본이 없을 때는 배틀만 사용할 수 없습니다.
- `MobiLife:ApiKey`<br>
  선택 설정입니다. [모비라이프 OpenAPI](https://open.mabimobi.life/docs) 키로, Discord 토큰처럼 로컬 개발은 user-secrets(`dotnet user-secrets set "MobiLife:ApiKey" "개발용_키"`), 서버는 환경변수 `MobiLife__ApiKey`(서비스용 키)로 설정합니다. 없으면 모비라이프 연동 기능만 안내 메시지를 표시하고 나머지 기능은 정상 동작합니다. `MobiLife:Enabled=false`로 호출을 끌 수 있습니다. 자세한 내용은 아래 `모비라이프 OpenAPI 사용`을 참고하세요.
- `assets/shop_table.csv`  
  일반 상점 데이터. 실행 시 자동 로드됩니다.
- `assets/shop_exchange_table.csv`  
  교환 상점 데이터. 실행 시 자동 로드됩니다.
- `assets/shop_share_table.csv`

## 동작 개요
- 랭킹 조회는 Playwright(Headless Chromium)로 페이지를 로드합니다.
- 이벤트 목록은 서버가 완성된 HTML을 내려주므로 브라우저 없이 HTTP로 직접 읽습니다. HTTP가 차단·오류로 실패할 때만 Playwright로 대체 수집하며, 대체 수집도 실패하면 10분 동안 브라우저를 다시 띄우지 않습니다.
- 이벤트 마감 알림은 KST 기준 **09:00 / 21:00**에 갱신됩니다.
- 이벤트 목록은 1분간 캐시합니다. 모든 페이지를 받아 검증을 통과한 목록만 반영하고, 수집에 실패하면 마지막 정상 목록을 `/진행중인이벤트`에 수집 시각과 함께 안내합니다.

## SQLite 저장

이벤트 마감 알림의 서버별 설정은 SQLite의 `event_expire_alert_settings` 테이블에 저장됩니다. 기존 `MOLLY_DATA_DIR/eventexpirealertsetting/<길드 ID>.json` 파일이 있으면 첫 시작에 SQLite로 안전하게 이전합니다. DB 트랜잭션이 성공한 JSON만 삭제하므로, JSON이 남아 있으면 다음 시작에 이전을 다시 시도합니다.

## 모비라이프 OpenAPI 사용

이 봇은 [모비라이프](https://mabimobi.life/)의 [OpenAPI](https://open.mabimobi.life/docs)를 사용합니다. 모비라이프 OpenAPI 데이터는 모비라이프가 제공하며, 넥슨(Nexon) 또는 데브캣(devCAT)의 공식 API가 아닙니다.

- 모비라이프 데이터를 사용하는 명령: `/해연시세모니터링`(거래소 시세 `market/prices`, 매 정각 검색어 5개 조회), `/상자시세모니터링`·`/패키지시세모니터링`(같은 API, 매 정각 각 검색어 1개 조회), 저장된 시세를 보여주는 `/해연시세`·`/해연시세모니터링테스트`·`/상자시세`·`/상자시세모니터링테스트`·`/패키지시세`·`/패키지시세모니터링테스트`.
- 모비라이프 데이터를 보여주는 모든 응답에는 출처 `모비라이프 제공`을 표기합니다.
- 키가 없거나 API가 중단·폐기되어도 봇의 다른 기능은 영향을 받지 않습니다.
- 이용약관, 키 설정, 요청 한도, 기능 추가 규칙과 중단 대비는 [모비라이프 OpenAPI 연동 가이드](docs/mobilife-openapi.md)를 따릅니다.

## 해연 시세 모니터링

`/해연시세모니터링`은 제작 시트에서 이름이 `해연의`로 시작하는 제작 아이템과 그 재료의 거래소 최저가를 추적합니다.

- 봇 시작 시 DB에 시세가 없거나 마지막 수집 이후 정각이 지났으면(예: 12:57 수집 후 13:03 시작) 즉시, 이후에는 매 정각(KST)에 모비라이프 시세를 `해연의`·`마력석`·`영혼석`·`특급`·`백금강괴`로 검색해 저장합니다. 검색 결과 중 제작 시트의 이름과 정확히 같은 항목만 사용합니다.
- 과거시세는 처음 수집한 시세로 시작합니다. 제작 아이템은 10%, 재료는 20% 이상 변동하면 알리고 과거시세를 현재시세로 갱신합니다.
- 완제품 최저가와 재료 구매 합계(재료 최저가×수량)를 비교해 더 저렴한 쪽(완제품 구매 / 재료 구매 후 제작)이 바뀌면 알립니다. 판매 수수료는 고려하지 않습니다. 둘의 차이가 3% 안이면 판정을 바꾸지 않아 같은 알림이 반복되지 않습니다.
- `세공된 페리도트ZZ`는 무가치한 재료로 보고 조회하지 않으며 0으로 계산합니다.
- 매진되었거나 매물이 3개 미만인 시세는 이력만 저장하고 그 회차의 변동·유불리 판정에서 뺍니다. 검색어 하나라도 조회에 실패하면 그 회차는 알림·저장 없이 건너뜁니다.
- 기준값(변동폭, 여유 폭, 최소 매물 수, 무가치 재료, 검색어, 이력 보관 90일)은 `HaeyeonMarket/HaeyeonMarketRules.cs`의 상수입니다.
- 알림에는 출처 `모비라이프 제공`을 표기합니다. 모비라이프 연동이 꺼져 있으면 등록은 되지만 수집은 되지 않습니다.
- 알림 채널·시간별 시세 이력·과거시세·유불리 상태는 SQLite의 `haeyeon_*` 테이블에 저장됩니다.
- `/해연시세`는 API를 부르지 않고 마지막 정각 수집에서 저장한 시세를 보여줍니다. 매진은 `매진`, 매물이 3개 미만이면 `적음`으로 표시합니다. `총해연재료`의 재료 합계는 재료 최저가×수량의 합이며, 시세가 없거나 매진인 재료가 있으면 계산하지 않고 그 재료를 알려줍니다.
- `/해연시세모니터링테스트`는 등록 채널이 아니라 명령을 실행한 채널에 `[테스트]` 알림을 보여주며 DB 상태를 바꾸지 않습니다.

## 상자·패키지 시세 모니터링

`/상자시세모니터링`은 거래소 `아이템` 분류에서 이름에 `상자`가 들어간 아이템 전체, `/패키지시세모니터링`은 분류 지정 없이 이름에 `패키지`가 들어간 아이템 전체의 최저가를 추적합니다(`KeywordMarket/`). 두 모니터링은 검색 조건만 다르고 등록·알림·저장은 서로 독립입니다.

- 수집 시점은 `/해연시세모니터링`과 같습니다. 봇 시작 시 시세가 없거나 직전 정각 수집을 놓쳤으면 즉시, 이후 매 정각(KST)에 모비라이프 시세를 검색해 저장합니다.
- 첫 수집 결과는 기준으로만 저장하고 알리지 않습니다. 이후 다음 경우에 알립니다.
  - 새로 올라온 아이템: 추적 중이 아니던 아이템이 검색됨. 사라졌던 아이템이 다시 올라와도 신규로 알립니다.
  - 사라진 아이템: 추적하던 아이템이 2회 연속(2시간) 검색되지 않음. 한 번만 빠졌다 돌아오면 알리지 않습니다.
  - 시세 변동: 과거시세 대비 10% 이상 변동하면 알리고 과거시세를 현재시세로 갱신합니다.
- 아이템은 거래소 `kind_id`로 구분합니다. 이름만 바뀐 아이템은 신규·사라짐으로 보지 않습니다.
- 매진되었거나 매물이 3개 미만인 시세는 이력만 저장하고 변동 판정에서 뺍니다(신규·사라짐 판정에는 포함). 조회에 실패했거나, 추적 중인데 검색 결과가 0건이면 그 회차는 알림·저장 없이 건너뜁니다. 검색 결과가 페이지 제한(500건)에 걸리면 그 회차는 사라짐을 판단하지 않습니다.
- 기준값(변동폭, 최소 매물 수, 사라짐 판정 횟수, 이력 보관 90일)과 검색 조건은 `KeywordMarket/KeywordMarketRules.cs`의 상수입니다.
- 알림에는 출처 `모비라이프 제공`을 표기합니다. 모비라이프 연동이 꺼져 있으면 등록은 되지만 수집은 되지 않습니다.
- 알림 채널·시간별 시세 이력·과거시세 상태는 SQLite의 `keyword_market_*` 테이블에 모니터링별(`box`·`package`)로 저장됩니다.
- `/상자시세`·`/패키지시세`는 API를 부르지 않고 마지막 정각 수집에서 저장한 아이템 전체를 이름순으로 보여줍니다. 매진은 `매진`, 매물이 3개 미만이면 `적음`으로 표시합니다.
- `/상자시세모니터링테스트`·`/패키지시세모니터링테스트`는 등록 채널이 아니라 명령을 실행한 채널에 `[테스트]` 알림을 보여주며 DB 상태를 바꾸지 않습니다.

## 제작 테이블 연동

같은 Google Sheets 문서의 `제작` 탭을 공용 레시피 데이터로 읽습니다(`Crafting/`). 여러 기능에서 함께 사용하며, 특정 기능의 조건은 사용하는 쪽에서 거릅니다.

- 첫 행에 `이름`과 `재료1`, `재료2`… 헤더를 유지하세요. 재료 셀은 `재료명/수량`(양의 정수) 형식이며 빈 칸은 건너뜁니다.
- `분류` 열(예: 무기·방어구·장신구)은 레시피 분류로 읽습니다. `/해연시세`의 `해연무기`·`해연방어구`·`해연장신구`가 이 값으로 아이템을 나누므로 해연 아이템의 분류 이름을 바꾸면 해당 종류에서 빠집니다.
- 이름이 비었거나 중복된 행, 형식이 잘못된 재료, 한 행 안의 중복 재료, 재료가 없는 행은 갱신 오류로 처리하고 마지막 정상본을 유지합니다.
- 시트 이름은 거래소 아이템 이름과 정확히 같아야 시세를 찾을 수 있습니다(예: `해연의 숏소드ZZ`).
- 시작 시 읽고, 사용하는 기능이 필요할 때 마지막 정상 갱신 후 10분이 지났으면 다시 읽습니다. 캐시는 `MOLLY_DATA_DIR/crafting/`에 저장합니다. 다른 탭 이름은 `GoogleSheets:CraftingSheetName` 또는 `GoogleSheets__CraftingSheetName`으로 설정합니다.

## 룬 테이블 연동

기본 데이터 원본은 [디스코드봇_몰리_테이블의 룬 탭](https://docs.google.com/spreadsheets/d/19kRuVIlZ1LEhU5lixEjRqYvZKbdGnXk0tjY6qznSRf0/edit?gid=0)입니다.
봇이 Google Sheets CSV를 직접 읽으므로, 해당 문서는 **링크가 있는 사용자에게 보기 허용** 상태여야 합니다. 별도의 Google 토큰이나 PowerShell, Playwright는 필요하지 않습니다. 봇은 시트를 수정하지 않습니다.

- 첫 행에 `시즌`, `등급`, `분류`, `클래스`, `이름`, `효과` 헤더를 유지하세요. 열 순서는 바꿔도 됩니다. `클래스`는 비워둘 수 있으며 장신구 룬 이름→클래스 퀴즈에서만 빈 행을 출제하지 않습니다.
- 시즌은 양의 정수, 등급은 `신화`·`전설`, 분류는 `무기`·`방어구`·`앰블럼`·`장신구`를 사용합니다.
- ID 열은 현재 시트에 없습니다. `시즌·등급·분류·이름` 조합으로 식별하며, 같은 조합의 중복 행은 갱신 오류로 처리합니다.
- 효과가 빈 행은 경고를 남기고 제외합니다. 쉼표·따옴표·셀 안 줄바꿈은 보존합니다.
- 시작 시 로컬 캐시를 읽고 시트를 갱신합니다. 이후 룬 데이터를 사용하는 명령이 실행될 때 마지막 정상 갱신 후 10분이 지났으면 다시 읽습니다. Google 측 CSV 반영 지연이 있을 수 있습니다.
- 통신 오류, 잘못된 헤더/값, 중복 행, 유효 데이터 0개 또는 캐시 저장 실패 시 마지막 정상본을 유지합니다. 최초 실행에 원본과 캐시가 모두 없으면 빈 상태로 시작하고 다음 갱신 때 재시도합니다.
- 캐시는 `MOLLY_DATA_DIR`(미설정 시 실행 파일 폴더) 아래 `runes/`에 원본별로 저장합니다. 이벤트 초기 수집 오류도 다른 기능의 시작을 중단시키지 않습니다.

다른 문서나 탭을 사용하려면 user-secrets의 `GoogleSheets:SpreadsheetId`, `GoogleSheets:RuneSheetId` 또는 환경변수 `GoogleSheets__SpreadsheetId`, `GoogleSheets__RuneSheetId`를 설정하세요. 탭 ID는 URL의 숫자 `gid`이며 현재 기본값은 `0`입니다.

`/병속에든쪽지`는 같은 문서의 `병 속에 든 쪽지` 탭에서 무작위 메시지를 골라 쪽지 모양 Embed로 표시합니다. 탭의 첫 행에는 `ID`, `메시지` 헤더를 유지하세요. ID와 메시지는 모두 비어 있지 않아야 하고, ID는 중복될 수 없으며 메시지는 3500자 이하여야 합니다. 데이터는 시작 시와 마지막 정상 갱신 후 10분이 지난 명령 실행 시 갱신합니다. 갱신 또는 검증에 실패하면 마지막 정상본을 계속 사용합니다. 다른 탭 이름은 `GoogleSheets:MessageBottleSheetName` 또는 `GoogleSheets__MessageBottleSheetName`으로 설정할 수 있습니다.

향후 명령에서는 한 번 읽은 스냅샷을 작업 동안 사용합니다:

```csharp
var table = Program.instance.Runes.Current;
var seasonRunes = table.Items.Where(r => r.Season == 2).ToArray();
var found = table.ByKey.TryGetValue(
    new Molly.Runes.RuneKey(2, "전설", "무기", "눈부신 잔영"), out var rune);
```

`Items.Count == 0`이면 데이터 준비 중 안내를 제공하세요. `LoadedAt`은 현재 정상본의 로딩 시각입니다. 필요하면 `Runes.RefreshAsync(ct)`로 직접 갱신할 수 있습니다. 공급 경로는 `IRuneSource`로 분리되어 있습니다.

Discord에서 `/룬`을 선택하고 `이름` 옵션에 `분노`를 입력하면 이름에 해당 텍스트가 포함된 모든 룬의 이름·시즌·등급·분류·클래스·효과를 보여줍니다. 검색어는 필수이며 공백만 입력할 수 없습니다. 앞뒤 공백은 제거하고 이름 내부의 공백은 그대로 비교합니다. 결과가 길면 나눠 보내며, 5개 메시지를 초과하는 결과는 전체 내용을 텍스트 파일로 제공합니다.

`/스피드퀴즈`는 `문제종목`, `문제수`(기본 10), `제한시간`(기본 30초)을 받아 **명령을 실행한 일반 텍스트 채널에 공개 스레드**를 만들고 그 안에서 진행합니다. 문제종목은 `시즌2룬효과로이름`, `시즌2무기룬효과로이름`, `시즌2방어구룬효과로이름`, `시즌2앰블럼룬효과로이름`, `시즌2장신구룬효과로이름`, `시즌2장신구룬빼고효과로이름`, `시즌2장신구룬이름으로클래스`를 지원합니다. 앞의 여섯 종목은 시즌 2에서 해당 대상의 효과를 보고 룬 이름을 맞히며, `시즌2장신구룬빼고효과로이름`은 장신구를 제외합니다. `시즌2장신구룬이름으로클래스`는 시즌 2 장신구 룬의 이름을 보고 클래스를 맞히며, 클래스가 비어 있는 행은 출제하지 않습니다. 요청한 문제수보다 데이터가 적으면 가능한 수만 출제합니다. 룬 이름 끝의 `+`는 정답에서 제거합니다. 준비 30초와 문제 사이 10초는 코드의 상수로 지정되어 있습니다. 길드당 한 게임만 진행하며, 정답은 띄어쓰기와 `+` 제거 및 영문 소문자 변환 후 비교합니다. 준비·문제 사이 대기는 5초 단위로 일반 메시지로 알리고, 문제 제한시간은 5초 단위 알림 뒤 마지막 3초에 강조된 `3·2·1` 메시지를 전송합니다. 정답 시 소요 시간도 표시합니다.

`/자음퀴즈`는 `문제종목`, `문제수`(기본 10), `제한시간`(기본 30초)을 받아 같은 방식으로 진행합니다. 종목은 `시즌2룬`, `시즌2무기룬`, `시즌2방어구룬`, `시즌2앰블럼룬`, `시즌2장신구룬`, `시즌2장신구룬빼고`, `NPC`, `클래스`, `지역`, `NPC+클래스+지역`입니다. 문제에는 `종류`와 정답의 자음을 표시합니다. 룬은 무기룬·방어구룬·장신구룬·앰블럼룬 힌트, NPC는 지역 힌트(빈 값은 `불명`), 지역은 분류 힌트를 표시하며 클래스에는 추가 힌트가 없습니다. NPC·지역·클래스 데이터는 같은 Google Sheets의 각 탭에서 읽으며, 세 탭을 모두 검증한 뒤 한 번에 갱신합니다.

`/진혹거퀴즈`는 `문제종목`, `문제수`(기본 10), `제한시간`(기본 30초)을 받아 같은 방식으로 실행 채널의 스레드에서 진행합니다. 문제 메시지에는 ✅(진실)와 ❌(거짓) 버튼을 표시하며, 참가자는 문제마다 첫 버튼 선택 하나만 할 수 있습니다. 제한시간 종료 시 정답 버튼을 고른 모든 참가자에게 1점씩 부여합니다. 룬 문제는 이름과 효과가 실제로 일치하면 진실, 같은 분류 안의 다른 룬 효과를 조합하면 거짓입니다. 따라서 무기·방어구·앰블럼·장신구는 물론 `시즌2룬`과 `시즌2장신구룬빼고` 종목도 이름의 분류 밖 효과를 섞지 않습니다. 문제마다 결과·현재 점수를 표시하고 마지막에 우승자 발표 후 스레드를 보관합니다.

스피드퀴즈·자음퀴즈·진혹거퀴즈는 길드마다 합쳐서 하나만 준비 또는 진행할 수 있습니다. `/놀이종료`를 사용하면 해당 길드의 진행 중인 게임을 즉시 종료하고, 게임 스레드에 지금까지의 점수와 현재 우승자를 최종 결과로 표시합니다. 종료 뒤 30초 동안 남은 시간을 알린 뒤 스레드를 읽기 전용으로 잠그고 보관합니다.

`자음표시`를 `true`로 선택하면 문제 Embed에 초성 힌트를 함께 표시합니다. `거대한 분노+`는 `ㄱㄷㅎ ㅂㄴ`로 표시되며, 띄어쓰기는 유지하고 `+` 같은 기호는 제외합니다. 카운트다운 일반 메시지와 별도로 힌트는 문제 Embed에 유지됩니다.

스피드퀴즈는 일반 메시지를 정답으로 받으므로 Discord Developer Portal에서 **Message Content Intent**를 켜야 합니다. 봇에는 공개 스레드 만들기, 스레드 관리, 채널 보기, 메시지 보내기 권한도 필요합니다. `/진혹거퀴즈`는 버튼 방식이라 반응 추가나 메시지 기록 보기 권한이 추가로 필요하지 않습니다.

봇 로그인·알림 없이 데이터만 확인하는 명령:

```bash

dotnet run --project tests/Molly.DataTests/Molly.DataTests.csproj --configuration Release -- --live
```

## 자동 검증과 Codex 개발 환경

- `main` push, pull request, 수동 실행 시 GitHub Actions CI가 실행됩니다.
- CI는 .NET 10 Release 빌드·오프라인 데이터 회귀 테스트·publish 및 이미지/CSV/Playwright 설치 스크립트의 배포 포함 여부를 검사합니다.
- Discord 접속·외부 페이지 수집·실제 Google Sheets 접속은 이 검증에 포함되지 않습니다.
- SDK는 `global.json`의 .NET 10 안정 버전을 사용합니다. Discord.Net은 3.20.1로 고정했습니다.

### 로컬 Mac / Codex CLI
.NET 10 SDK를 설치한 뒤 프로젝트를 갱신하고 검증하세요.

```bash
git pull --ff-only
bash scripts/setup.sh
```

스크립트는 .NET 10 SDK가 없으면 `.tools/dotnet`에 설치하고, 빌드 검증까지 수행합니다.
기본 실행은 Chromium을 설치하지 않습니다. 실제 봇 실행 전에는 빠른 시작의 브라우저 설치 단계를 별도로 수행하세요.
PowerShell 7(`pwsh`)이 있다면 `INSTALL_PLAYWRIGHT=1 bash scripts/setup.sh`로 빌드 검증과 Chromium 설치를 함께 수행할 수 있습니다.
최초 설치·패키지 복원에는 네트워크가 필요합니다. 이후 변경 검증 명령은 다음과 같습니다.

```bash
bash scripts/verify.sh
```

스크립트가 설치한 SDK를 터미널에서 직접 사용하려면:
```bash
export DOTNET_ROOT="$PWD/.tools/dotnet"
export PATH="$DOTNET_ROOT:$PATH"
```
시스템에 SDK를 설치했다면 위 환경변수 설정은 필요 없습니다.

### Codex 클라우드 환경
- 이 저장소를 작업 대상으로 연결합니다.
- 환경의 setup 명령: `bash scripts/setup.sh`
- 준비 단계에서 dot.net, Microsoft SDK 다운로드 호스트 및 NuGet 접근이 필요합니다.
- 일반 코드·빌드 작업에는 Discord 토큰과 Chromium이 필요하지 않습니다.
- Codex는 루트 `AGENTS.md`를 개발 지침으로 사용합니다.
- 이 저장소에는 환경 준비 스크립트가 포함되어 있으며, 계정의 Codex 환경 설정 자체는 별도로 지정해야 합니다.

### 실제 실행에 필요한 추가 준비
아래 Playwright 설치 스크립트에는 PowerShell 7의 `pwsh`가 필요합니다. `pwsh`가 없는 Apple Silicon Mac은 빠른 시작의 대체 명령을 사용하세요.
Release 빌드 후:
```bash
pwsh bin/Release/net10.0/playwright.ps1 install chromium
```
Linux에서 브라우저 시스템 라이브러리가 부족하면 관리자 권한으로
`pwsh bin/Release/net10.0/playwright.ps1 install --with-deps chromium`을 실행하세요.

실제 실행은 기존 빠른 시작의 토큰·테스트 서버 설정을 따르세요.
저장 경로는 예를 들어 `MOLLY_DATA_DIR="$PWD/.molly-data"`로 지정할 수 있습니다.
